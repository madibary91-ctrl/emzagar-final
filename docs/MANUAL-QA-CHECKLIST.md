## 0) راهنمای استفاده و علامت‌ها

### علامت‌های اولویت
| علامت | معنی |
|---|---|
| **[P0]** | بدون سبز بودنش لانچ ممنوع (پول، امضا، امنیت، از دست رفتن داده) |

| **[P2]** | بهبود کیفیت؛ می‌تواند بعد از لانچ باشد |

### علامت‌های محل اجرا
| علامت | معنی |
|---|---|
| 📱 | روی گوشی واقعی |
| 💻 | روی کامپیوتر |
| 📩 | پیامک واقعی (نه حالت `log`) |
| 🏦 | درگاه بانکی واقعی با مبلغ کم |
| 🌐 | روی سرور اصلی (نه localhost) |
| 🧪 | فقط روی محیط آزمایشی/شبیه‌ساز (چون روی سرور اصلی خطرناک یا پرهزینه است) |
| 🔧 | نیاز به دسترسی سرور (SSH/Docker/پایگاه‌داده) |

### قاعده‌ی ثبت نتیجه
برای هر بند یکی از این‌ها را بنویسید:
- ✅ درست بود
- ❌ خراب بود (فوراً در بخش ۷ ثبت کنید، با عکس/ویدیو)
- ➖ قابل اجرا نبود (با دلیل)

برای هر ❌ ذکر کنید: **شناسه‌ی بند، دستگاه/مرورگر، زمان دقیق، لینک صفحه، عکس‌صفحه‌ی کامل، متن خطا**. اگر ممکن است ویدیوی ضبط صفحه بگیرید. پیام‌هایی که برای کاربر نمایش داده می‌شود را عیناً کپی کنید.

### شناسه‌ی بندها
`S06-12` یعنی بند ۱۲ از بخش S06. در متن، `→` یعنی «انتظار می‌رود». هر چه بعد از `→` نیامد، همان رفتار طبیعی است.

### سه قانون طلایی
1. **ابتدا روی محیط آزمایشی، سپس روی سرور اصلی.** هر چیزی که بعد از انجامش برگشت ندارد (حذف حساب، بازپرداخت واقعی، ارسال پیامک انبوه) فقط با حساب‌های آزمایشی و شماره‌های خودتان.
2. **یک بار مرورگر عادی، یک بار پنجره‌ی ناشناس.** بسیاری از باگ‌های نشست (login/logout) فقط در حالت دوم دیده می‌شود.
3. **هر تست را حداقل یک بار با دست «شکسته» اجرا کنید.** مثلاً در میانه‌ی کار wifi را قطع کنید، دوبار روی دکمه بزنید، دکمه‌ی Back را بزنید، صفحه را رفرش کنید.

- [ ] **[P0]** یک سرور «آزمایشی» (staging) با همان نسخه، همان دامنه‌ی فرعی (مثلاً `test.دامنه`)، **دیتابیس جدا**، و درگاه/پیامک همان واقعی ولی با مبلغ کم.
- [ ] **[P0]** سرور اصلی (production) با `https://دامنه‌ی نهایی` و گواهی HTTPS معتبر.
- [ ] **[P0]** 🔧 دسترسی SSH و توانایی مشاهده‌ی لاگ برنامه (`docker compose logs -f app` یا معادل) در حین تست. در هر تست مهم یک پنجره‌ی لاگ باز نگه دارید و دنبال خطای قرمز بگردید.

## 3) سفرهای طلایی

> **این هشت سفر را اول انجام دهید.** هر سفر یک مسیر کامل از اول تا آخر است. اگر یکی از این‌ها ❌ شد، ابتدا رفعش کنید و بعد سراغ بخش‌ها بروید. همه را 🌐 و 📩 و (جایی که پول است) 🏦 اجرا کنید.

### J1 [P0] — «اولین روز مشتری تازه»
- [ ] ثبت‌نام با ایمیل جدید ← ایمیل تأیید در Inbox می‌رسد (نه Spam) ← کلیک لینک ← ورود
- [ ] راهنمای شروع (Onboarding) ← تنظیم نام شرکت و لوگو
- [ ] صدور اولین قرارداد از قالب نمونه ← امضاکننده‌ی GUEST-1 با موبایل واقعی ← 📩 پیامک لینک می‌رسد
- [ ] باز کردن لینک روی 📱 ← OTP 📩 ← امضا ← «قرارداد نهایی شد»
- [ ] ایمیل نسخه‌ی نهایی با PDF می‌رسد ← PDF در گوشی باز می‌شود ← فارسی درست دیده می‌شود
- [ ] صفحه‌ی استعلام `/verify/<هش>` ← «معتبر»

### J2 [P0] — «قرارداد دو طرفه‌ی ترتیبی»
- [ ] OWNER-A قرارداد با دو امضاکننده‌ی ترتیبی (GUEST-1 سپس GUEST-2) صادر می‌کند
- [ ] GUEST-2 قبل از نوبتش لینک را باز می‌کند → پیام «هنوز نوبت شما نرسیده»؛ امضا ممکن نیست
- [ ] GUEST-1 امضا می‌کند ← GUEST-2 اعلان می‌گیرد ← امضا می‌کند ← قرارداد نهایی
- [ ] هر دو و فرستنده PDF نهایی را دریافت می‌کنند

### J3 [P0] — «خرید اشتراک با درگاه بانکی» 🏦
- [ ] ارتقا از طرح رایگان به «حرفه‌ای» ← انتخاب درگاه ← پرداخت واقعی ← بازگشت به سایت
- [ ] اشتراک فعال، سقف‌ها بالا رفته، فاکتور PDF شماره‌دار، اعلان
- [ ] بازگشت دوباره به صفحه‌ی نتیجه (Refresh) → دوباره پرداخت ثبت نمی‌شود

### J4 [P0] — «پرداخت ناموفق و انصراف»
- [ ] شروع پرداخت و انصراف در صفحه‌ی بانک ← بازگشت ← «ناموفق» و هیچ اشتراک/موجودی تغییر نکرده
- [ ] تکرار با موجودی کم/رمز دوم غلط

### J5 [P0] — «شاهد + مهر + پاراف + هم‌زمان»
- [ ] قرارداد با: COMPANY (حقوقی، مهر الزامی، پاراف الزامی)، GUEST-1 (حقیقی)، WITNESS
- [ ] ترتیب: دو طرف هم‌زمان ← شاهد پس از هر دو
- [ ] PDF نهایی: مهر روی امضا، پاراف پایین هر صفحه، برچسب «شاهد:»، هش در پاورقی

### J6 [P0] — «لغو و رد»
- [ ] صادرکننده قرارداد را لغو می‌کند ← لینک امضا بسته می‌شود ← امضاکنندگان اطلاع می‌گیرند
- [ ] امضاکننده قرارداد را رد می‌کند (با دلیل) ← وضعیت «رد شده» ← صادرکننده اعلان می‌گیرد

### J7 [P0] — «بازیابی بلایا»
- [ ] 🔧 بک‌آپ کامل ← حذف کامل نمونه (روی سرور آزمایشی!) ← بازیابی ← همه‌ی قراردادها، فایل‌ها، PDFها و ورود کاربران کار می‌کند

### J8 [P1] — «وردپرس»
- [ ] نصب افزونه روی سایت واقعی ← اتصال خودکار ← صدور قرارداد از فرم/ووکامرس ← امضا ← بازگشت وضعیت به وردپرس

> **یادآوری نهایی:** هیچ فهرستی کامل نیست. هر باگ واقعی که بعد از لانچ پیدا شد، یک **بند جدید** به همین سند اضافه کنید (با شناسه‌ی بخش مربوط). این سند باید با محصول زنده بماند.
