# راهنمای تست و تضمین کیفیت

## ۱) تست‌های خودکار (Vitest + PostgreSQL آزمایشی `emz_test`)
```bash
npx vitest run                    # همه‌ی تست‌ها (واحد + یکپارچه)
npx vitest run tests/unit         # فقط واحد (بدون دیتابیس)
npx vitest run tests/integration/inbox-privacy-renewal.test.ts
```
دیتابیس `emz_test` هر بار از نو ساخته می‌شود؛ هرگز به دیتابیس واقعی دست نمی‌زند. Server Actionها و Route Handlerها مستقیم با شبیه‌ساز کوکی/هدر اجرا می‌شوند.

| فایل | پوشش |
|---|---|
| `unit/fields.test.ts` | تجزیه‌ی توکن، کد ملی/تاریخ/تلفن/ایمیل، XSS در جایگزینی، اثر انگشت، تشخیص نوع فایل، منطق تمدید |
| `integration/signing.test.ts` | امضای مهمان با لینک+OTP، PDF و هش، مسیر حساب کاربری |
| `integration/fields-attachments-amendments.test.ts` | فیلدها (اجباری/نامعتبر/تزریق/قفل در هش/دستکاری)، پیوست (امنیت، حجم، جعل، دسترسی، دستکاری دیسک)، الحاقیه (OTP، نسخه، PDF، رد، دسترسی) |
| `integration/inbox-privacy-renewal.test.ts` | اعلان‌ها (جریان، dedupe، ایزولاسیون، API)، نشست‌ها و دستگاه‌ها، خروجی داده، حذف حساب، زمان‌بندی تمدید و زمان‌بند |
| `integration/registration|otp|payment|backup` | ثبت‌نام و تأیید ایمیل، OTP، پرداخت، بک‌آپ/بازیابی |

## ۲) تست دودی روی سرور در حال اجرا
```bash
npm run build && npm run start &          # یا سرور پیش‌نمایش
node scripts/smoke.mjs http://127.0.0.1:3000
```
صفحه‌های عمومی، هدایت صفحه‌های محافظت‌شده، ۴۰۱ شدن APIها، صفحه‌ی خطای لینک نامعتبر، هدرهای امنیتی و ۴۰۴.

## ۳) اعتبارسنجی پیش از تحویل
```bash
npx next typegen && npm exec tsc -- --noEmit && npm run build && npx eslint src tests --quiet
```

## ۴) چک‌لیست تست دستی (۱۵ تا ۲۰ دقیقه)
**فیلدها**
- [ ] در ویرایشگر قالب، «+ کد ملی» و «+ نشانی» را درج و قرارداد صادر کنید.
- [ ] در صفحه‌ی امضا فرم «اطلاعات لازم در قرارداد» نمایش داده می‌شود؛ کد ملی غلط خطا می‌دهد؛ ارقام فارسی پذیرفته می‌شود.
- [ ] پس از امضا مقدارها در متن قرارداد (سبز) و PDF دیده می‌شود؛ استعلام `/verify/<hash>` «معتبر» است.

**پیوست**
- [ ] آپلود PNG/PDF موفق؛ فایل `.exe` یا HTML با پسوند png رد می‌شود؛ فایل بالای ۵MB رد می‌شود.
- [ ] لینک دانلود فایل را در پنجره‌ی ناشناس باز کنید → ورود لازم است.
- [ ] روی موبایل دکمه‌ی انتخاب فایل از دوربین/گالری کار می‌کند.

**الحاقیه**
- [ ] قرارداد امضاشده → ثبت الحاقیه → هر امضاکننده از لینک ایمیل با OTP تأیید می‌کند → نسخه ۲ و دکمه‌ی «PDF الحاقیه».
- [ ] رد یک نفر → وضعیت «رد شده» و امکان ثبت الحاقیه‌ی جدید.

**اعلان**
- [ ] زنگوله پس از امضای طرف مقابل شمارنده می‌گیرد؛ کلیک روی اعلان به قرارداد می‌رود و خوانده می‌شود.
- [ ] روی موبایل پنل زنگوله تمام‌عرض و بدون سرریز است؛ Esc آن را می‌بندد.

**حریم خصوصی**
- [ ] «حساب من ← نشست‌ها»: با دو مرورگر وارد شوید؛ از یکی دیگری را ببندید (با رفرش بعدی خارج می‌شود).
- [ ] «دانلود همه‌ی داده‌های من» فایل JSON می‌دهد و رمز در آن نیست.
- [ ] حذف حساب: بدون عبارت/رمز صحیح انجام نمی‌شود؛ با حساب آزمایشی انجام و ورود دوباره ممکن نیست.

**تمدید**
- [ ] در صفحه‌ی قرارداد امضاشده، پایان مدت را ۱۰ روز بعد و یادآوری ۳۰ روز قبل بگذارید؛ `POST /api/cron/run` اعلان می‌سازد (دوبار اجرا ⇒ یک اعلان).
- [ ] «ساخت پیش‌نویس تمدید» به ویرایش پیش‌نویس می‌رود؛ `/admin/renewals` وضعیت «تمدید شده» را نشان می‌دهد.

**ریسپانسیو و دسترس‌پذیری**
- [ ] عرض ۳۶۰، ۷۶۸، ۱۴۴۰: بدون اسکرول افقی در صفحه‌ی قرارداد، حساب من، اعلان‌ها و تمدیدها.
- [ ] تب‌گردی با کیبورد؛ برچسب فرم‌ها و `aria` زنگوله؛ حالت تیره.
