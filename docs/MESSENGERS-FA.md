# ربات‌های پیام‌رسان — بله، تلگرام (دوطرفه) و ایتا (یک‌طرفه)

هدف: کاهش وابستگی به پیامک و ایمیل. امضاکننده و مدیر کسب‌وکار **داخل پیام‌رسان** لینک امضا را می‌گیرند، وضعیت قرارداد را می‌بینند، یادآوری می‌فرستند و اعلان‌ها را دریافت می‌کنند.

## معماری (یک نگاه)

```
                          ┌──────────── پنل: /admin/messengers  (ربات اختصاصی فضای کاری)
 مدیر ── ثبت توکن ربات ──▶│             /platform/messengers    (ربات پلتفرم برای همه‌ی کاربران)
                          └─▶ getMe + setWebhook | deleteWebhook(Polling) + setMyCommands

 رویدادهای سامانه                           صف کارهای ماندگار (Outbox، backoff، retry)
  ├ notifyUser (زنگوله) ───────────────────▶ messenger.notice    ┐
  ├ notifySigner (صدور/نوبت/یادآوری) ──────▶ messenger.signlink  ├─▶ deliver() ─▶ Bot API (بله/تلگرام)
  ├ تکمیل قرارداد ─────────────────────────▶ messenger.finalcopy ┘     └ دکمه‌ی URL، تکه‌کردن پیام، مسدودشدن چت
  └ deliverSigningOtp (کد امضا) ── هم‌زمان، کوتاه‌مهلت ─▶ فقط چت با «شماره‌ی گواهی‌شده»؛ پیامک فقط در صورت ناموفق‌بودن

 کاربر ─▶ POST /api/messengers/webhook/<راز>  (یا Polling با اجاره‌ی دیتابیسی)
          └▶ bot.ts: /pending /contracts /status /summary /verify /mute /stop + دکمه‌ها (وضعیت، امضا، یادآوری، نسخه‌ی نهایی)
```

- **یک آداپتور برای بله و تلگرام**: Bot API بله مانند تلگرام است (`tapi.bale.ai`). داخل ایران بله بدون فیلتر کار می‌کند.
- **ایتا**: API ایتا (ایتایار) فقط ارسال به کانال/گروه دارد (بدون وب‌هوک/دکمه/پیام خصوصی)؛ بنابراین در «اعلان پیام‌رسان» (`/admin/webhooks`) به‌عنوان مقصد یک‌طرفه‌ی تیم اضافه شد، نه ربات دوطرفه.
- **ربات پلتفرم + ربات اختصاصی**: `workspaceId = null` ربات همه‌ی کاربران؛ ربات هر فضای کاری فقط قراردادهای همان فضا را نشان می‌دهد (جداسازی تنانت در `contractAccess`).

## راه‌اندازی

1. در بله به `@botfather` یا در تلگرام به `@BotFather` پیام بدهید، با `/newbot` ربات بسازید و توکن را بگیرید.
2. `/platform/messengers` (مدیر کل) یا `/admin/messengers` (مدیر تیم) ← توکن را وارد کنید.
   - سایت HTTPS دارد ← «وب‌هوک» (پیش‌فرض؛ `APP_URL` باید HTTPS باشد).
   - هاست اشتراکی/بدون HTTPS عمومی ← «Polling» (پردازش هر ۴ ثانیه؛ با اجاره‌ی دیتابیسی فقط یک پردازه می‌پرسد).
   - سرور ایرانی و تلگرام ← «آدرس رله» (مثلاً Cloudflare Worker که به `api.telegram.org` پروکسی می‌کند؛ از فیلتر SSRF می‌گذرد).
3. از «حساب من ← پیام‌رسان‌ها» وصل شوید و «ارسال پیام آزمایشی» را بزنید.

## هویت و امنیت

| موضوع | تصمیم |
|---|---|
| توکن ربات | AES-256-GCM در دیتابیس؛ هرگز به مرورگر/لاگ/خطا برنمی‌گردد (خطاها پاک‌سازی می‌شوند) |
| وب‌هوک | راز ۱۹۲ بیتی در آدرس + برای تلگرام هدر `X-Telegram-Bot-Api-Secret-Token` (مشتق‌شده) ؛ ناهمخوانی ⇒ ۴۰۴ |
| آپدیت تکراری | جدول `messenger_updates` (یکتا روی bot+update_id) |
| اتصال حساب | کد یک‌بارمصرف ۱۰ دقیقه‌ای (فقط هش)، مصرف اتمیک؛ برای مهمان کد امضاشده‌ی HMAC کوتاه‌عمر که فقط همان مهمان را وصل می‌کند |
| **شماره‌ی گواهی‌شده** | فقط با دکمه‌ی «اشتراک شماره» و `contact.user_id == from.id`؛ مخاطب فوروارد/دستی رد می‌شود |
| **OTP امضا** | فقط به چت‌هایی که *شماره‌ی خودِ امضاکننده* را گواهی کرده‌اند؛ چت وصل‌شده با لینک به‌تنهایی کافی نیست (وگرنه OTP دیگر عامل دوم نبود) |
| گروه‌ها | ربات فقط در گفتگوی خصوصی پاسخ می‌دهد |
| PDF نهایی | پیش‌فرض خاموش (فایل از سرور خارجی عبور می‌کند)؛ روشن‌کردن: فقط برای طرف‌های امضاشده/عضو تیم با هویت گواهی‌شده |
| لینک امضا در صف | در payload صف ذخیره نمی‌شود؛ در لحظه‌ی ارسال ساخته می‌شود و وضعیت قرارداد دوباره سنجیده می‌شود |
| نرخ | ۴۵ پیام در دقیقه برای هر چت؛ ۴۲۹ پیام‌رسان ⇒ تلاش مجدد با backoff؛ ۴۰۳ (مسدودشدن ربات) ⇒ چت `blocked` |

## امکانات کاربر در پیام‌رسان

`/pending` لینک امضای قراردادهای منتظر شما · `/contracts` فهرست · `/status <شماره>` وضعیت و امضاکنندگان · `/summary` خلاصه‌ی تیم (منتظر امضا، امضاشده، مهلت <۷۲ ساعت) · دکمه‌ی «یادآوری به امضاکنندگان» (اعضای تیم، حداکثر ساعتی یک‌بار) · دکمه‌ی «نسخه‌ی نهایی» · `/verify` · `/mute` `/unmute` · `/stop`.

پشتیبان‌ها: `/chats` (گفتگوهای آنلاین بی‌پاسخ) و `/done`، و دکمه‌های «پاسخ از همین‌جا / برعهده‌گرفتن» در اعلان گفتگوی آنلاین — [CHAT-ALERTS-FA.md](CHAT-ALERTS-FA.md).

## تنظیمات هر ربات

- **کد تأیید امضا**: `prefer` (پیام‌رسان؛ پیامک فقط اگر نرسید — کم‌هزینه) · `both` · `off`.
- **ارسال PDF نهایی** (پیش‌فرض خاموش).
- **روش دریافت**: وب‌هوک / Polling.

## جدول‌ها

`messenger_bots` · `messenger_chats` · `messenger_link_codes` · `messenger_updates` · `messenger_log` (بدون متن پیام). ساخت و ارتقا خودکار است (`src/db/schema.ts` ← نصب‌کننده).

## آزمون

`tests/unit/messengers-util.test.ts` و `tests/integration/messengers.test.ts` (Bot API جعلی با `EXTERNAL_SIM_URL`: ثبت ربات، رمزنگاری توکن، امنیت وب‌هوک، جعل شماره، لینک امضا، OTP از پیام‌رسان، اعلان، بی‌صدا، جداسازی فضای کاری، Polling، تکراری‌ها).

## محدودیت‌های شناخته‌شده

- ظرفیت ارسال ربات معمولی بله بر پایه‌ی تعامل کاربر است؛ برای اعلان انبوه از «API کسب‌وکاری بله» (پولی) استفاده کنید (فقط `base URL` متفاوت است).
- روبیکا و ایتا ربات دوطرفه ندارند/ناقص‌اند؛ ایتا برای کانال/گروه یک‌طرفه پشتیبانی می‌شود.
