# نسخه‌ی سازمانی افزونه (۲.۳.۰) — راهنمای قابلیت‌ها

این سند ۵ نکته‌ی حیاتیِ معمار ارشد و افزوده‌های خلاقانه را توضیح می‌دهد. همه‌چیز داخل پیشخوان وردپرس، زیر منوی **امضاگیر** است.

| صفحه | مسیر | کلاس |
|---|---|---|
| تنظیمات (۵ تب) | امضاگیر ← تنظیمات | `Emzagar_Settings` |
| وضعیت سیستم | امضاگیر ← وضعیت سیستم | `Emzagar_Health` |
| راهنمای شروع | امضاگیر ← راهنمای شروع | `Emzagar_Onboarding` |

---

## ۱) خروجی کامل داده‌ها (Data Export / Import)  — `Emzagar_Export`

**تنظیمات ← داده‌ها و پشتیبان**

- **JSON کامل**: تنظیمات، ماژول‌ها، محدودیت‌ها، اتوماسیون‌ها، اتصال فرم‌ها، لاگ اجرا، صندوق فعالیت، دروازه‌های محتوا، قالب محصولات و (اختیاری) تا ۱۰۰۰ قرارداد از ابر؛ با `checksum` و نسخه‌ی `schema`.
- **CSV هر بخش** (UTF‑8 با BOM برای اکسل فارسی؛ محافظت در برابر Formula Injection: سلول‌های شروع‌شونده با `= + - @` با `'` خنثی می‌شوند).
- **ZIP** حاوی JSON و همه‌ی CSVها.
- **اسرار هرگز خروجی نمی‌شوند** (کلید API، راز همگام‌سازی، توکن‌ها).
- **ورود/بازگردانی**: فایل JSON با اعتبارسنجی؛ هر فیلد دوباره پاک‌سازی می‌شود (مثلاً وب‌هوک غیر http(s) حذف می‌شود)؛ انتخاب بخش‌ها؛ پیش از اعمال پشتیبان خودکار گرفته می‌شود.
- **پشتیبان خودکار پیش از هر به‌روزرسانی افزونه و هر ورود داده** + دکمه‌ی «بازگردانی آخرین پشتیبان».
- WP‑CLI: `wp emzagar export --file=backup.json --contracts`

## ۲) کلید فعال/غیرفعال (Feature Flag) + سپر ایمنی — `Emzagar_Modules`

**تنظیمات ← ماژول‌ها** — ۱۲ ماژول مستقل: همگام‌سازی، دروازه‌ی قرارداد، مرکز فرماندهی، اعلان زنده، میز کار کانبان، پالت فرمان، اتوماسیون، فرم‌ها، شورت‌کدها، ووکامرس، رابط سفارش‌ها، المنتور.

- خاموش‌کردن یک ماژول **داده‌ها و قوانین را پاک نمی‌کند** و بقیه‌ی سیستم دست‌نخورده کار می‌کند.
- **مدار شکن (Circuit Breaker)**: خطای شدید (Fatal) داخل فایل یک ماژول ⇒ همان ماژول خودکار خاموش می‌شود، علت/فایل/خط ثبت می‌شود و اعلان قرمز با دکمه‌ی «روشن‌کردن دوباره» نشان داده می‌شود. استثناهای قابل‌گرفتن در راه‌اندازی هم همین‌طورند.
- **حالت امن**: همه‌ی ماژول‌های اختیاری با یک کلیک (هسته‌ی اتصال/تنظیمات می‌ماند).
- **وقتی به پیشخوان دسترسی ندارید**: در `wp-config.php`
  ```php
  define( 'EMZAGAR_SAFE_MODE', true );
  define( 'EMZAGAR_DISABLE_MODULES', 'automations,forms' );
  ```
  یا `wp emzagar modules disable forms` · فیلتر کد: `add_filter('emzagar_module_enabled', fn($on,$id)=>…, 10, 2)`.
- صفحه‌ی اتوماسیون برای «فرم‌ها» هم لازم است؛ پس با خاموش بودن فقط اتوماسیون، تب «فرم‌ها» در دسترس می‌ماند و برعکس.

## ۳) ویزارد خوش‌آمدگویی — `Emzagar_Onboarding`

پس از فعال‌سازی، مدیر یک‌بار به **راهنمای شروع** می‌رود: خوش‌آمد و وضعیت اتصال ← کانبان (با نمای کوچک) ← اتوماسیون (**راه‌اندازی یک‌کلیکی ۳ دستور پرکاربرد**) ← فرم‌ها (فرمسازهای نصب‌شده) ← ایمنی و داده ← فهرست پیشرفت **واقعی** (از وضعیت سایت تشخیص داده می‌شود، نه تیک دستی). گام جاری ذخیره می‌شود؛ بدون JavaScript هم همه‌ی گام‌ها دیده می‌شود؛ کلیدهای ← → کار می‌کنند؛ از منو هر زمان قابل بازگشت است.

## ۴) وضعیت سیستم (Local Health Check) — `Emzagar_Health`

چراغ سبز/زرد/قرمز برای ۲۰+ بررسی در ۵ گروه:

| گروه | بررسی‌ها |
|---|---|
| اتصال به ابر | آدرس، کلید API، HTTPS، **پینگ زنده با میلی‌ثانیه**، دسترسی ابر به REST خود سایت |
| Heartbeat | ضربان روزانه (آخرین موفق/خطا)، WP‑Cron (عقب‌افتادگی و `DISABLE_WP_CRON`)، صف همگام‌سازی، Heartbeat زنده‌ی وردپرس |
| اتوماسیون/فرم | نرخ موفقیت ۲۰ اجرای اخیر، چند خطای پشت‌سرهم ⇒ قرمز، آخرین اجرا، فرمساز نصب‌نشده |
| ایمنی | قفل اضطراری، سقف روزانه، ماژول‌های خاموش/خودکار-خاموش |
| سیستم | PHP، حافظه، ووکامرس، لایسنس، به‌روزرسانی |

- بررسی‌های شبکه‌ای با AJAX و زنده (هر ۶۰ ثانیه تازه می‌شود)؛ صفحه هرگز با کندی ابر کند نمی‌شود.
- نشان قرمز تعداد مشکل‌ها کنار منو (۲ دقیقه کش).
- **نقطه‌ی پایش بیرونی** با توکن: `GET /wp-json/emzagar/v1/health?token=…[&live=1]` ⇒ ۲۰۰ سالم/هشدار، ۵۰۳ مشکل جدی (UptimeRobot، Better Stack).
- `wp emzagar health [--live] [--format=json]` (کد خروج ۱ در مشکل جدی).

## ۵) محدودیت نرخ و قفل اضطراری — `Emzagar_Limits`

**تنظیمات ← محدودیت و امنیت** — علاوه بر نادیده‌گرفتن ارسال تکراری (همان ایمیل+قالب ۱۰ دقیقه):

| لایه | پیش‌فرض |
|---|---|
| سقف روزانه‌ی کل قراردادهای صادرشده از فرم‌ها | ۱۰۰ |
| هر IP در ساعت | ۱۰ |
| هر ایمیل در روز | ۳ |
| هر کاربر در ساعت (شورت‌کد درخواست قرارداد) | ۵ |
| **تشخیص موج اسپم**: تلاش در ۱۰ دقیقه ⇒ قفل خودکار ۶۰ دقیقه‌ای + ایمیل به مدیر | ۳۰ |

- **قفل اضطراری دستی**: دکمه‌ی قرمز در تب؛ نوار قرمز در نوار مدیریت وردپرس؛ `wp emzagar lockdown on|off|status`.
- شمارنده‌ها با `UPDATE` اتمیک روی جدول options (سازگار با درخواست‌های هم‌زمان، بدون وابستگی به object cache) و پاک‌سازی روزانه.
- خطای ابر ⇒ سهمیه‌ی رزروشده برمی‌گردد (کاربر بی‌گناه از سقف نمی‌سوزد).
- خریدهای ووکامرس (پرداخت واقعی) **هرگز** مسدود نمی‌شوند؛ فقط فرم‌های عمومی و شورت‌کد.
- پشت CDN/پراکسی: `add_filter('emzagar_client_ip', …)`.

## ۶) لایسنس و به‌روزرسانی Turnkey

| لایه | چه می‌کند |
|---|---|
| سرور فروشنده (موجود از قبل) | لایسنس Ed25519-امضاشده، سهمیه‌ی دامنه، مهلت آفلاین ۱۴ روز، انتشار نسخه |
| ابر خریدار (VPS) | فعال‌سازی لایسنس؛ **جدید:** `GET /api/v1/connect/update-check` (با کلید API) نسخه‌ی افزونه‌ی همراه + وضعیت لایسنس را می‌دهد |
| افزونه‌ی وردپرس (**جدید**) | `Emzagar_Updater`: هر ۱۲ ساعت می‌پرسد؛ به‌روزرسانی از ابر خودتان؛ خودکار برای نسخه‌های هم‌خانواده؛ پیش از نصب پشتیبان می‌گیرد؛ بسته فقط از همان میزبان ابر (HTTPS) و با بررسی ساختار zip |

نمایش در **تنظیمات ← لایسنس و به‌روزرسانی**: نسخه‌ی نصب‌شده/جدید، تغییرات، وضعیت لایسنس (پلن، دامنه، پایان، دسترسی به آپدیت، ظرفیت دامنه). اگر `LICENSE_REQUIRED=1` و لایسنس نامعتبر باشد، بسته‌ی جدید عرضه نمی‌شود اما افزونه‌ی نصب‌شده **کار می‌کند**.

استقرار: [`DEPLOYMENT-GUIDE-FA.md`](DEPLOYMENT-GUIDE-FA.md) — `scripts/install-vps.sh`، `docker-compose.prod.yml` (Caddy + HTTPS خودکار)، `scripts/vps-backup.sh`، `scripts/vps-update.sh` (بازگشت خودکار).
