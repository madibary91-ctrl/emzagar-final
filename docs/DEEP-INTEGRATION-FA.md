# یکپارچگی عمیق با وردپرس — «امضاگیر» به بخشی از کسب‌وکار تبدیل می‌شود

هدف: کاربر وردپرسی امضاگیر را «یک افزونه‌ی امضا» نبیند؛ آن را بخشی از **ماشین کسب‌وکار** خودش ببیند —
جایی که مدیریت قرارداد، کنترل دسترسی مشتری، فروشگاه و گزارش‌های روزانه را انجام می‌دهد.

> اصل طراحی: وابستگی از **ارزش واقعی** ساخته می‌شود، نه از گروگان‌گرفتن داده. داده‌ی مشتری همیشه قابل دریافت (خروجی/بکاپ) است،
> افزونه هرگز سایت را از کار نمی‌اندازد و هیچ «کلید خاموشی» پنهانی ندارد. مشتری می‌ماند چون جایگزین‌کردن این سیستم یعنی
> بازسازی ده‌ها اتوماسیون، دروازه و عادت کاری.

## ۱) مرکز فرماندهی کسب‌وکار (داخل پیشخوان وردپرس)
- **نشان زنده روی نوار مدیریت** (در همه‌ی صفحه‌ها): تعداد قراردادهای منتظر امضا + میانبر «صدور قرارداد»، «پنل» و «نیازمند اقدام».
- **ویجت پیشخوان «نبض کسب‌وکار»**: منتظر امضا، امضا در ۳۰ روز، موارد نیازمند اقدام؛ با بارگذاری ناهمزمان (پیشخوان را کند نمی‌کند).
- **صفحه‌ی «مرکز فرماندهی»** (`امضاگیر ← مرکز فرماندهی`):
  - شاخص‌ها: ارزش سفارش‌های منتظر امضا، میانه‌ی زمان امضا، انقضای نزدیک، تمدیدهای نزدیک.
  - **صف اقدام**: قراردادهای بی‌پاسخ (۳+ روز)، نزدیک انقضا (۴۸ ساعت)، ردشده و تمدیدهای سررسیده؛ «یادآوری» تکی و گروهی با یک کلیک.
  - **ارزش‌آفرینی**: قرارداد بسته‌شده، ساعت کار دستی حذف‌شده (برآورد ۴۵ دقیقه/قرارداد)، ارزش قراردادها، روند ۱۴ روزه.
  - **عمق یکپارچگی** با گام بعدی پیشنهادی.
- **گزارش هفتگی ایمیلی** (یکشنبه ۸ صبح؛ هفته‌ی کاملاً بی‌فعالیت مزاحم نمی‌شود) + دکمه‌ی گزارش آزمایشی.
- **سلامت سایت وردپرس**: آزمون «اتصال امضاگیر» در `ابزارها ← سلامت سایت`.

## ۲) دروازه‌ی قرارداد — امضا، کلید دسترسی سایت می‌شود
| قابلیت | چطور |
|---|---|
| قفل صفحه/نوشته/هر نوع محتوا | کادر «قفل قرارداد (امضاگیر)» در ویرایشگر؛ «هر قرارداد امضاشده» یا «قرارداد X» |
| قفل بخشی از متن | `[emzagar_gate template_id="12"] … [/emzagar_gate]` |
| خرید محصول فقط پس از امضا | همان کادر روی محصول؛ افزودن به سبد و پرداخت مسدود می‌شود |
| مسیر خودکار برای مشتری | ورود ← (اگر قرارداد دارد) لینک امضا ← (اگر ندارد) دریافت قرارداد با یک فرم |
| REST | محتوای قفل‌شده از `/wp-json/wp/v2/...` هم نشت نمی‌کند |
| نقش خودکار | پس از امضا، نقش انتخابی (پیش‌فرض آماده: «مشتری امضاکننده») داده و با لغو/انقضا پس گرفته می‌شود؛ مدیران هرگز تغییر نمی‌کنند |
| کارت مشتری | پروفایل هر کاربر + ستون «قرارداد» در فهرست کاربران |
| API توسعه‌دهنده | `emzagar_user_has_signed( $user_or_email, $template_id )`، هوک‌های `emzagar_user_signed`، `emzagar_contract_signed_for_email`، `emzagar_user_unsigned`، `emzagar_contract_event` و فیلتر `emzagar_gate_fail_open` |

**شاخص محلی امضاها**: رویدادهای ابر در وردپرس هم ثبت می‌شود؛ حتی اگر ابر لحظه‌ای در دسترس نباشد، مشتریان امضاکرده بیرون نمی‌مانند.
اگر شاخص محلی پاسخ ندارد، افزونه از ابر می‌پرسد (کش ۴۵ ثانیه برای «خیر» و ۱ ساعت برای «بله»). در قطع ارتباط، پیش‌فرض بسته است
(`add_filter('emzagar_gate_fail_open','__return_true')` برای باز بودن).

> رویدادهای قرارداد حالا برای **همه‌ی قراردادهای فضای کاری** (نه فقط سفارش‌های ووکامرس) به سایت وردپرسِ متصل می‌رسد.

## ۳) نشان اعتماد — دارایی اعتباری کسب‌وکار
- صفحه‌ی عمومی `/trust/<slug>`: قراردادهای امضاشده، نرخ تکمیل، میانه‌ی زمان امضا و دامنه‌های تاییدشده. نام مشتریان و متن قراردادها هرگز نمایش داده نمی‌شود.
- روی سایت: خودکار پایین صفحه یا با `[emzagar_trust]` (پیش‌فرض خاموش؛ مدیر فعال می‌کند).

## ۴) عمق یکپارچگی (سمت پلتفرم)
افزونه میزان ادغام خود (بدون هیچ داده‌ی شخصی) گزارش می‌دهد: تعداد دروازه‌ها، قرارداد روی محصولات، اتوماسیون سفارش، نقش خودکار،
نشان، گزارش هفتگی، پورتال، کابین فرماندهی و تعداد دفعاتی که دسترسی بر پایه‌ی امضا باز شده است.
- امتیاز ۰–۱۰۰ و چهار سطح: **شروع ← فعال ← یکپارچه ← هسته‌ی کسب‌وکار**.
- نمایش در وردپرس (مرکز فرماندهی) و در پنل (`/admin/wordpress`) همراه با «گام پیشنهادی بعدی».
- برای فروشنده‌ی SaaS: معیار عینی پذیرش (Adoption) هر مشتری و پیش‌بینی ریزش.

## نقاط API جدید (کلید API)
| مسیر | کاربرد |
|---|---|
| `GET/POST /api/v1/hub/pulse` | نبض کسب‌وکار؛ POST با `{features}` عمق یکپارچگی را ثبت می‌کند |
| `POST /api/v1/hub/access` | `{email, templateIds?}` ← آیا قرارداد امضاشده‌ی معتبر دارد؟ (یا لینک امضای قرارداد منتظر) |
| `GET /api/v1/hub/customer?email=` | کارت ۳۶۰ درجه‌ی مشتری (قراردادها + سفارش‌ها) |
| `GET /trust/<slug>` | صفحه‌ی عمومی اعتماد |

همه‌ی مسیرها به فضای کاری کلید محدودند (ایزولاسیون چندمستاجری آزموده شده) و محدودیت نرخ جداگانه دارند.

# مرکز فرماندهی کامل (افزونه‌ی ۲٫۲)

هدف: مدیر سایت برای مدیریت قراردادها، مشتریان و کارهای روزمره **هرگز مجبور نشود از پیشخوان وردپرس بیرون برود**.

| قابلیت | کجا؟ | توضیح |
|---|---|---|
| **میز کار قراردادها** | امضاگیر ← میز کار قراردادها | کانبان زنده، فهرست و جستجو، کشوی جزئیات (امضاکنندگان، خط زمانی، لینک امضا)، یادآوری، لغو، دانلود PDF رسمی، صدور قرارداد با پرکردن خودکار از کاربران/مشتریان وردپرس، پیوند به سفارش ووکامرس و پروفایل کاربر |
| **پالت فرمان Ctrl/⌘+K** | همه‌ی صفحه‌های پیشخوان | پرش به هر صفحه (از منوی خود وردپرس)، اقدام سریع، جستجوی یکپارچه‌ی قرارداد/مشتری/قالب + نوشته/محصول/کاربر/سفارش |
| **اعلان زنده** | همه‌ی صفحه‌های پیشخوان | Toast لحظه‌ای هنگام امضا (WordPress Heartbeat)، زنگ فعالیت روی نوار مدیریت، صندوق فعالیت |
| **اتوماسیون «اگر … آنگاه»** | امضاگیر ← اتوماسیون‌ها | ۸ دستور آماده‌ی یک‌کلیکی و سازنده‌ی قانون دلخواه؛ کنش‌ها: وظیفه، ایمیل به مدیر/مشتری، نقش کاربری، وضعیت/یادداشت سفارش، قرارداد بعدی (زنجیره)، وب‌هوک. اجرای آزمایشی امن و گزارش اجرا |
| **فرم‌ها ← قرارداد** | اتوماسیون‌ها ← فرم‌ها | CF7، WPForms، Gravity Forms، Elementor Pro، Fluent Forms؛ نام/ایمیل/موبایل خودکار تشخیص داده می‌شود |
| **ارسال قرارداد از فهرست کاربران** | کاربران | اقدام تکی و گروهی (با قالب پیش‌فرض) |
| **WP-CLI** | ترمینال | `wp emzagar status|contracts|remind|issue|pulse|automations` |

## نقاط API جدید (کلید API)
| مسیر | کاربرد |
|---|---|
| `GET /api/v1/hub/pipeline?per=8` | ستون‌های کانبان (ارسال‌شده، مشاهده‌شده، امضاشده، ردشده، منقضی/لغو) با شمار و ارزش |
| `GET /api/v1/hub/contract/<id>` | جزئیات قرارداد + خط زمانی + لینک امضای نفر بعدی |
| `GET /api/v1/hub/search?q=` | جستجوی یکپارچه‌ی قرارداد/مشتری/قالب |
| `POST /api/v1/contracts/<id>/cancel` | لغو قرارداد در انتظار امضا `{reason?}` |
| `GET /api/v1/contracts/<id>/pdf` | PDF رسمی قرارداد امضاشده (وردپرس آن را پراکسی می‌کند؛ کلید هرگز به مرورگر نمی‌رسد) |
| `GET /api/v1/contracts?q=` | پارامتر جستجوی آزاد به فهرست قراردادها اضافه شد (و فیلد `value`) |

## امنیت
- همه‌ی درخواست‌های AJAX با nonce و `manage_options` محافظت می‌شوند؛ کلید API فقط روی سرور وردپرس می‌ماند.
- رابط‌های جاوااسکریپت فقط با `textContent` می‌نویسند (بدون `innerHTML`)، لینک‌های پالت فقط http(s).
- وب‌هوک اتوماسیون با `wp_safe_remote_post` (مسدودسازی آدرس‌های داخلی/SSRF).
- اقدام «نقش» هرگز نقش مدیر نمی‌دهد و مدیران را تغییر نمی‌دهد؛ زنجیره‌ی قرارداد با همان قالب مجاز نیست (ضد چرخه).
- فرم‌ها: ارسال تکراریِ همان ایمیل در ۱۰ دقیقه نادیده گرفته می‌شود.

## عمق یکپارچگی (به‌روز)
گام‌های جدید امتیاز: میز کار (۱۰)، اتوماسیون (۱۰)، فرم‌ها (۵)، اعلان زنده و پالت (۵). میزان «کنش‌های بدون خروج از وردپرس»، قوانین فعال، اجرای اتوماسیون و فرم‌های متصل در `/admin/wordpress` دیده می‌شود.
