# همگام‌سازی دوطرفه‌ی ووکامرس ↔ امضاگیر (پروتکل نسخه ۲)

## نمای کلی

```
 ووکامرس ──(صف محلی، HMAC، دسته‌ای)──►  POST /api/v1/sync/events      ──► جدول wc_orders (آینه‌ی سفارش‌ها)
 ووکامرس ◄──(Push امضاشده)────────────  /wp-json/emzagar/v1/events    ◄── صف خروجی wp_outbox
 ووکامرس ──(هر ۵ دقیقه، با ACK)──────►  POST /api/v1/sync/pull        ──► همان صف (برای سایت‌های پشت فایروال)
```

| جهت | چه چیزی | چطور |
|---|---|---|
| وردپرس → ابر | سفارش‌ها (ثبت/وضعیت/استرداد/حذف)، مشتریان | صف محلی `{prefix}emzagar_queue`؛ ادغام رویدادهای تکراری؛ بار رویداد در لحظه‌ی ارسال از آخرین وضعیت سفارش ساخته می‌شود؛ ارسال دسته‌ای ≤۵۰ |
| ابر → وردپرس | صدور، امضا، تکمیل، رد، انقضا، لغو، یادآوری قرارداد | صف `wp_outbox`: Push فوری امضاشده؛ در صورت ناممکن بودن Pull توسط افزونه؛ backoff نمایی؛ ماندگاری ۷ روز |
| ترمیم | رویداد ازدست‌رفته | افزونه هر ساعت وضعیت قراردادهای بازِ ۴۵ روز اخیر را با `GET /api/v1/contracts?ids=…` از ابر می‌پرسد |

## امنیت

* هر درخواست: `Authorization: Bearer emz_…` **و** امضای HMAC-SHA256: `X-Emzagar-Signature: sha256=hex(HMAC(secret, "<timestamp>.<rawBody>"))` + `X-Emzagar-Timestamp` (ثانیه). پنجره‌ی ۵ دقیقه‌ای = ضد بازپخش.
* راز مشترک (۳۲ بایت) با `POST /api/v1/sync/handshake` به افزونه تحویل می‌شود؛ در ابر با AES-256-GCM (`enc:v1`) ذخیره می‌شود. چرخش از پنل («چرخش راز امضا») → افزونه خودکار راز جدید را می‌گیرد.
* ایدمپوتنت: هر رویداد شناسه‌ی یکتا دارد؛ ابر (`wp_inbound`) و افزونه (حلقه‌ی ۳۰۰ شناسه‌ی آخر) تکراری‌ها را نادیده می‌گیرند. پس Push + Pull هم‌زمان یا ارسال مجدد هرگز اثر دوباره ندارد.
* ترتیب: رویداد سفارشِ قدیمی‌تر (بر اساس `updatedAt`) هرگز داده‌ی جدیدتر را بازنویسی نمی‌کند؛ وضعیت نهایی قرارداد هرگز به «در انتظار» برنمی‌گردد.
* به‌روزرسانی مشتری فقط برای کاربرانِ نقش `user` که عضو همان فضای کاری‌اند.
* سقف نرخ جداگانه برای مسیرهای sync (۲۴۰ درخواست/دقیقه به‌ازای هر کلید).
* ارسال سفارش و مشتری از «امضاگیر ← همگام‌سازی» قابل خاموش‌کردن است؛ متن حریم خصوصی به صفحه‌ی خط‌مشی وردپرس اضافه می‌شود.

## نقاط API

| مسیر | توضیح |
|---|---|
| `POST /api/v1/sync/handshake` | `{rotate?, capabilities?}` ← `{secret, secretAt, protocol}` |
| `POST /api/v1/sync/events` | `{events:[{id,type,at,data}]}` ← `{results:[{id,status: ok\|duplicate\|ignored\|error}]}` |
| `POST /api/v1/sync/pull` | `{ack?:[ids], limit?}` ← `{events, pending, secretAt}` |
| `POST /api/v1/contracts` | `external:{source:"woocommerce",orderId,productId,key}` ← صدور ایدمپوتنت (`reused:true` در تکرار) |
| `GET /api/v1/contracts?ids=1,2` | عکس لحظه‌ای وضعیت قراردادها (هم‌ترازسازی) |
| `POST /api/v1/contracts/{id}/remind` | یادآوری امضا (۳ بار در ساعت) |

رویدادهای ورودی: `order.upserted` · `order.deleted` · `customer.upserted` · `sync.ping`
رویدادهای خروجی: `contract.issued|signed|completed|rejected|expired|cancelled|reminder` · `sync.ping` · `sync.resync`

## رفتار خودکار ابر

* سفارش `cancelled / failed / refunded / trash` شد → قراردادهای **امضانشده‌ی** همان سفارش خودکار لغو می‌شوند (و رویداد لغو به وردپرس برمی‌گردد).
* لینک امضا و وضعیت هر قرارداد روی سفارش (یادداشت سفارش، ستون فهرست، کادر سفارش، صفحه‌ی تشکر، ایمیل، حساب کاربری) نمایش داده می‌شود.

## اتوماسیون اختیاری در وردپرس (تنظیمات ← همگام‌سازی)

* نگه‌داشتن سفارش پرداخت‌شده تا امضا (`on-hold`) و آزادسازی خودکار پس از امضای همه.
* پس از امضا: فقط یادداشت / `processing` / `completed`.
* پس از رد، انقضا یا لغو: فقط یادداشت / `on-hold` / `cancelled`.
* قفل دانلود محصولات مجازی تا امضا (و فعال‌سازی خودکار پس از امضا).

## پنل ابر

`/admin/woocommerce` — سلامت اتصال (سالم / ارتباط قدیمی / نیازمند توجه / بدون ارتباط)، KPI فروش و امضا، فهرست سفارش‌ها با وضعیت امضا، گزارش زنده‌ی دوطرفه، و دکمه‌های: آزمایش اتصال، هم‌ترازسازی کامل، ارسال مجدد صف، توقف/ازسرگیری، چرخش راز.

## عیب‌یابی

| نشانه | علت/راه‌حل |
|---|---|
| «Pull دوره‌ای» به‌جای «Push فوری» | ابر نمی‌تواند به `/wp-json/emzagar/v1/events` برسد (فایروال/حفاظت REST). مشکلی نیست؛ رویدادها تا ≤۵ دقیقه با Pull می‌رسند. |
| `stale_timestamp` | ساعت سرور وردپرس بیش از ۵ دقیقه اختلاف دارد؛ NTP را فعال کنید. |
| `bad_signature` | راز چرخیده؛ افزونه خودکار دوباره دست می‌دهد (یا «دریافت مجدد کلید امضا»). |
| رویدادی نمی‌رسد | `DISABLE_WP_CRON` فعال است؟ یک Cron سیستمی برای `wp-cron.php` بسازید. |
