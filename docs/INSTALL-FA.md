# راهنمای نصب امضاگیر (برای کاربران مبتدی)

> **هدف: بدون هیچ دستور خط فرمان.** سه راه دارید؛ ساده‌ترین را انتخاب کنید.
> در هر سه راه، بقیه‌ی کار را «نصب‌کننده‌ی وب» انجام می‌دهد: آزمایش دیتابیس، ساخت جدول‌ها، ساخت کلید امنیتی، ساخت حساب مدیر و ورود خودکار.

## راه ۱ — هاست cPanel / DirectAdmin (پیشنهادی برای مبتدی‌ها)

نیاز: هاستی که **Node.js** (نسخه ۲۰ به بالا) و **PostgreSQL** داشته باشد.

1. فایل `emzagar-x.y.z.zip` (بسته‌ی آماده‌ی خریداری‌شده) را در «مدیریت فایل» هاست آپلود و **Extract** کنید.
2. در پنل، بخش **PostgreSQL Databases** یک دیتابیس و یک کاربر بسازید و کاربر را به دیتابیس وصل کنید (همه‌ی دسترسی‌ها).
   _اگر نمی‌توانید، از پشتیبانی هاست «اطلاعات اتصال PostgreSQL» را بخواهید._
3. بخش **Setup Node.js App ← Create Application**:
   - Node.js version: `20` یا بالاتر
   - Application root: پوشه‌ی استخراج‌شده
   - Application startup file: `app.js`
   - دکمه‌ی **Create** و بعد **Run / Restart**
4. آدرس سایت را در مرورگر باز کنید. صفحه‌ی **نصب** خودکار می‌آید؛ اطلاعات دیتابیس و حساب مدیر را وارد کنید. تمام!

> 🔐 **کلید نصب (امنیت):** نصب‌کننده «همیشه» اثبات مالکیت سرور می‌خواهد؛ بازدیدکننده‌ی ناشناس نمی‌تواند مدیر شود. کلید را یکی از این سه راه پیدا کنید: ۱) مقدار `INSTALL_KEY` اگر خودتان در Environment variables گذاشته‌اید؛ ۲) فایل `storage/install-key.txt` (در «مدیریت فایل» هاست)؛ ۳) لاگ برنامه (`docker compose logs app`). پس از پایان نصب، فایل کلید خودکار حذف می‌شود. اگر دیتابیس پیکربندی‌شده موقتاً قطع باشد، نصب‌کننده برای امنیت **بسته** می‌ماند (برای شروع از صفر، `storage/config.json` را حذف کنید).

### اگر مشکل پیش آمد
| پیام | راه‌حل |
|---|---|
| «پوشه‌ی storage قابل نوشتن نیست» | در مدیریت فایل روی پوشه‌ی `storage` ← Permissions ← `755` یا `775` |
| «نام کاربری یا رمز دیتابیس اشتباه است» | در بخش PostgreSQL هاست رمز کاربر را دوباره تعیین کنید |
| «سرور دیتابیس پاسخ نمی‌دهد» | آدرس سرور را از پشتیبانی هاست بپرسید (معمولاً `localhost`) |
| «نسخه‌ی Node.js پایین است» | در Setup Node.js App نسخه را ۲۰ یا بالاتر بگذارید |

## راه ۲ — Docker (VPS، Coolify، CapRover، Portainer …)

فایل `docker-compose.yml` همراه پروژه است (برنامه + PostgreSQL). در پنل‌هایی مثل Coolify/Portainer همان فایل را Paste کنید؛ یا روی سرور یک بار:

```bash
docker compose up -d
```

سپس `http://IP-سرور:3000` را باز کنید. دیتابیس از قبل متصل است و نصب‌کننده فقط **نام سایت و حساب مدیر** را می‌پرسد.
داده‌ها در volumeهای `dbdata` و `storage` می‌مانند. برای HTTPS، دامنه را از پنل (یا Nginx/Caddy/Cloudflare) به پورت ۳۰۰۰ وصل کنید و `APP_URL` را روی آدرس دامنه بگذارید.

## راه ۳ — سرور حرفه‌ای (برای توسعه‌دهنده‌ها)

```bash
npm ci && npm run build && npm start      # نصب‌کننده‌ی وب هم‌چنان بعد از اجرا در /install در دسترس است
```

یا متغیرهای محیطی `DATABASE_URL` و `SESSION_SECRET` را مستقیم بدهید (مرحله‌ی دیتابیس نصب‌کننده رد می‌شود).

## برای فروشنده: ساخت «بسته‌ی آماده‌ی» مارکت‌پلیس

```bash
node scripts/build-release.mjs     # خروجی: release/emzagar-1.0.0.zip
```

این بسته همه‌چیز را از قبل ساخته و ردیابی‌شده دارد (بدون نیاز به `npm install` و بدون نیاز به دیتابیس هنگام ساخت). نسخه را با `RELEASE_VERSION=1.2.0` تعیین کنید.
اگر `src/db/schema.ts` را تغییر دادید، پیش از ساخت بسته یک بار اجرا کنید: `node scripts/gen-schema-sql.mjs` تا SQL نصب‌کننده به‌روز شود
(جدول‌ها و ستون‌های جدید هنگام نصب/ارتقا خودکار ساخته می‌شوند؛ اجرای دوباره‌ی نصب‌کننده روی دیتابیس موجود بی‌خطر است).

## پشتیبان‌گیری
فقط دو چیز مهم است: **دیتابیس PostgreSQL** و **پوشه‌ی `storage`** (امضاها، تصاویر، فایل `config.json` شامل کلید رمزنگاری). هر دو را با هم پشتیبان بگیرید؛ با گم‌شدن `config.json` رمزهای ذخیره‌شده‌ی SMTP/پیامک/هوش مصنوعی باید دوباره وارد شوند.

## ویرایش صفحه‌ی اصلی
پس از ورود: منوی **«ویرایشگر صفحه اصلی»** (فقط مدیر کل). متن، تصویر، رنگ، ترتیب بخش‌ها و منو را با کلیک عوض کنید؛ تغییرات خودکار به‌عنوان پیش‌نویس ذخیره می‌شود و با دکمه‌ی **انتشار** روی سایت می‌آید. از تب «نسخه‌ها» می‌توانید به هر نسخه‌ی قبلی برگردید.
