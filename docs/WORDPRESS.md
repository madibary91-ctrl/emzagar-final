# افزونه‌ی وردپرس امضاگیر — نصب بدون تنظیم

پوشه‌ی افزونه: `wordpress-plugin/emzagar-contracts`

## تجربه‌ی کاربر: نصب ← فعال‌سازی ← کار می‌کند
1. در پنل امضاگیر: **وردپرس و ووکامرس ← دانلود افزونه** (فایل ZIP از پیش پیکربندی‌شده).
2. وردپرس ← افزونه‌ها ← افزودن ← بارگذاری افزونه ← **فعال‌سازی**.
3. تمام. افزونه خودش وصل می‌شود؛ کلیدی کپی نمی‌شود و فرمی پر نمی‌شود.

بعد از اتصال، در منوی «امضاگیر» وردپرس: **باز کردن پنل امضاگیر** (ورود یک‌کلیکی، بدون رمز)، شورت‌کدها، ویجت‌های المنتور و تنظیمات ووکامرس آماده‌اند.

## پشت صحنه (معماری اتصال خودکار)
```
WordPress                                        Cloud (Next.js)
  │  فعال‌سازی                                        │
  │── POST /api/v1/connect/register ───────────────► │  چالش تصادفی + handshakeId
  │      {installId, siteUrl, adminEmail, …}          │
  │  (چالش روی /wp-json/emzagar/v1/verify)            │
  │── POST /api/v1/connect/complete ───────────────► │
  │                                  ◄── GET verify ─│  تایید مالکیت دامنه (ضد SSRF)
  │ ◄───────────── apiKey (فقط یک‌بار) ──────────────│  فضای کاری + قالب‌های نمونه + کلید
```
- **تایید مالکیت دامنه**: ابر مسیر REST خود سایت را از بیرون می‌خواند و باید همان چالشِ یک‌بارمصرف را ببیند. بنابراین کسی نمی‌تواند به‌نام دامنه‌ی دیگران ثبت‌نام کند.
- **سایت‌های محلی/آزمایشی** (localhost، `.test`، `.local`، HTTP): بدون تایید، در حالت آزمایشی وصل می‌شوند.
- **نصب مجدد روی همان دامنه**: همان فضای کاری و داده‌ها برمی‌گردند (کلید قدیمی باطل و کلید تازه صادر می‌شود).
- **خودترمیمی**: اگر کلید باطل شود، افزونه در پس‌زمینه دوباره وصل می‌شود (با فاصله‌ی تلاش افزایشی). ضربان روزانه نسخه‌ها و آخرین ارتباط را ثبت می‌کند.
- **حذف افزونه**: کلید باطل می‌شود؛ قراردادها و قالب‌ها در حساب می‌مانند.
- **امنیت ایمیل**: اگر ایمیل مدیر وردپرس قبلاً در پلتفرم حساب داشته باشد، اتصال ناشناس هرگز به آن حساب وصل نمی‌شود (فضای کاری جداگانه). برای وصل به حساب موجود از دانلود شخصی‌سازی‌شده (کد جفت‌سازی یک‌بارمصرف، ۷ روز اعتبار) استفاده کنید.
- **ورود یک‌کلیکی (SSO)**: توکن ۹۰ ثانیه‌ای و یک‌بارمصرف؛ فقط برای فضاهای کاری که حساب مالک را خود اتصال خودکار ساخته (نه مدیر کل پلتفرم).

## چه چیزی «بدون تنظیم» کار می‌کند؟
- **کد تایید امضا**: اگر پنل پیامک تنظیم نشده باشد، ابتدا پیامک مدیریت‌شده‌ی پلتفرم (`PLATFORM_SMS_*`) و در غیاب آن ایمیل (SMTP پلتفرم) استفاده می‌شود.
- **ایمیل‌ها**: فضای کاری بدون SMTP اختصاصی از SMTP پلتفرم (`SMTP_*`) استفاده می‌کند.
- **صفحه‌ی «قراردادهای من»** برای سایت‌های بدون ووکامرس خودکار ساخته می‌شود؛ در ووکامرس تب «قراردادها» به حساب کاربری اضافه می‌شود.
- **قالب پیش‌فرض** پس از اتصال خودکار انتخاب می‌شود.

## تنظیمات سرور (ابر)
- `APP_URL` را حتماً در production تنظیم کنید؛ آدرس داخل ZIP دانلودی از آن ساخته می‌شود.
- برای انتشار عمومی، می‌توانید در ZIP عمومی هم آدرس را ثابت کنید: ثابت `EMZ_DEFAULT_CLOUD_URL` در `emzagar-contracts.php` یا `define('EMZAGAR_CLOUD_URL', '…')` در `wp-config.php`.
- نقاط API: `POST /api/v1/connect/register|complete` (عمومی با محدودیت نرخ)، `GET|POST /api/v1/connect/status`، `POST /api/v1/connect/sso|disconnect` (با کلید).

## حالت پیشرفته (سرور اختصاصی)
«امضاگیر ← تنظیمات ← تنظیمات پیشرفته»: آدرس سرور و کلید API را دستی وارد کنید؛ اتصال به حالت دستی می‌رود و خودترمیمی در آن دخالت نمی‌کند.

## شورت‌کدها (سازگار با المنتور، گوتنبرگ، Divi، WPBakery …)
| شورت‌کد | توضیح |
|---|---|
| `[emzagar_dashboard]` | داشبورد قراردادهای کاربر واردشده؛ آمار، فیلتر وضعیت، صفحه‌بندی. پارامترها: `status` `per_page` `show_stats="yes/no"` `scope="mine/all"` `title` |
| `[emzagar_stats]` | کارت‌های آمار (کل، امضا شده، در انتظار، نرخ تکمیل) |
| `[emzagar_request_contract template_id="12"]` | فرم درخواست قرارداد برای کاربر واردشده. پارامترها: `template_id` `button` `title` |

`scope="all"` فقط برای مدیر سایت کار می‌کند. کاربر عادی فقط قراردادهای خودش (بر پایه‌ی ایمیل حساب وردپرس) را می‌بیند.

## المنتور
دسته‌ی **«امضاگیر»** سه ویجت دارد: داشبورد قراردادها، آمار قراردادها و فرم درخواست قرارداد؛ رنگ و تایپوگرافی از تب «استایل» قابل تنظیم است.

## ووکامرس
- در ویرایش محصول (تب «عمومی») **قالب قرارداد امضاگیر** را انتخاب کنید.
- پس از پرداخت (یا تکمیل سفارش؛ از تنظیمات) قرارداد صادر و لینک امضا در صفحه‌ی تشکر، جزئیات سفارش و ایمیل نمایش داده می‌شود؛ هر محصول در هر سفارش فقط یک‌بار قرارداد می‌گیرد.
- تب **قراردادها** در «حساب کاربری من» (پس از فعال‌سازی یک‌بار «پیوندهای یکتا ← ذخیره» را بزنید).

## نکته‌ی عیب‌یابی
ابر برای تایید دامنه، آدرس `/?rest_route=/emzagar/v1/verify` را از بیرون می‌خواند. اگر سایت در حالت «به‌زودی/نگهداری» است، رمز Basic-Auth دارد یا افزونه‌ی امنیتی REST API را مسدود کرده، اتصال با پیام «ابر نتوانست سایت شما را تایید کند» به تعویق می‌افتد و خودکار تکرار می‌شود. روی هاست‌های تک‌پردازشی (مثل `php -S`) تایید به‌دلیل قفل شدن درخواست داخلی ممکن نیست؛ روی هاست‌های معمول مشکلی ندارد.

## مرکز فرماندهی و دروازه‌ی قرارداد (نسخه‌ی ۲٫۱)
نوار مدیریت زنده، ویجت پیشخوان، صف اقدام، گزارش هفتگی، قفل قرارداد روی محتوا/محصول، نقش خودکار پس از امضا، نشان اعتماد و عمق یکپارچگی — جزئیات و API: `docs/DEEP-INTEGRATION-FA.md`.
شورت‌کدهای جدید: `[emzagar_gate template_id="12"] … [/emzagar_gate]` و `[emzagar_trust]`.
