# راهنمای عملیات — تأیید ایمیل، امضای بدون ثبت‌نام، PDF، تست و بک‌آپ

## ۱) تأیید ایمیل
- ثبت‌نام: ساخت حساب ← ارسال کد ۶ رقمی + لینک (۳۰ دقیقه) ← **تا تأیید، نشست ساخته نمی‌شود**.
- ورود با ایمیل تأییدنشده هم به همین صفحه می‌رود. «فراموشی رمز» هم مالکیت ایمیل را ثابت می‌کند.
- ایمیل‌های یک‌بارمصرف و دامنه‌های بدون MX/A رد می‌شوند. هر کد حداکثر ۵ تلاش دارد؛ ارسال مجدد هر ۶۰ ثانیه.
- حساب‌های موجود هنگام ارتقا خودکار «تأییدشده» علامت می‌خورند. نیازمند SMTP (یا `SMTP_*` پلتفرم) است.

## ۲) امضای بدون ثبت‌نام
- هر امضاکننده یک لینک اختصاصی `/sign/<توکن ۲۵۶ بیتی>` دارد (فقط هش آن در دیتابیس).
- مشتری: باز کردن لینک ← کد پیامکی (OTP) ← مطالعه ← امضا. هیچ ثبت‌نام یا رمزی لازم نیست.
- لینک پس از امضا/رد/لغو/انقضا باطل می‌شود؛ نوبت‌بندی رعایت می‌شود. مدیر در صفحه‌ی قرارداد لینک را کپی/ارسال مجدد می‌کند.
- API: پاسخ `POST /api/v1/contracts` فیلد `signUrl` دارد (و `shortUrl` هم به آن اشاره می‌کند).

## ۳) PDF سمت سرور
- پس از امضای آخرین نفر، PDF با قلم وزیرمتن ساخته و در `storage/documents` (خارج از public، مجوز ۰۶۰۰) ذخیره می‌شود.
- SHA-256 فایل در `contract_documents` ثبت و هنگام هر دانلود بررسی می‌شود (مغایرت = خطای ۴۰۹ + لاگ).
- PDF به ایمیل همه‌ی طرفین پیوست می‌شود. دانلود: `/api/contracts/<id>/pdf` (حساب) یا صفحه‌ی امضا (مهمان).

## ۴) تست و بک‌آپ
- `npm test` — روی دیتابیس جدا `emz_test` (خودکار ساخته می‌شود؛ `TEST_DATABASE_URL` برای تغییر).
- `npm run backup` / `npm run backup -- list` / `npm run backup -- verify` — بک‌آپ دستی؛ برنامه‌ی داخلی هر ۲۴ ساعت خودش می‌گیرد. مدیر کل از `/platform` هم می‌تواند فوری بگیرد.
- `npm run restore -- <پوشه‌ی بک‌آپ> --yes` — بازیابی (بدون `--yes` فقط صحت بررسی می‌شود). بک‌آپ ناسالم هرگز اعمال نمی‌شود.
- **حتماً** `BACKUP_DIR` را روی دیسک/سرور دیگر بگذارید یا پوشه‌ی بک‌آپ را به مقصد خارجی (rsync/S3) همگام کنید؛ بک‌آپ روی همان دیسک در برابر خرابی دیسک محافظت نمی‌کند.
