# راهنمای استقرار روی VPS (برای خریداران) — نسخه‌ی Turnkey

این راهنما برای کسی است که یک سرور مجازی (VPS) خریده و می‌خواهد «ابر امضاگیر» را روی دامنه‌ی خودش با **HTTPS خودکار** راه بیندازد، لایسنس را فعال کند و افزونه‌ی وردپرس را وصل کند. آشنایی با برنامه‌نویسی لازم نیست؛ فقط کپی/پیست چند دستور.

---

## ۰) پیش‌نیازها

| مورد | حداقل | توضیح |
|---|---|---|
| سیستم‌عامل | Ubuntu 22.04 / 24.04 یا Debian 12 | تمیز و تازه نصب‌شده |
| منابع | ۲ هسته CPU، ۲ گیگ RAM، ۲۰ گیگ دیسک | برای ۱۰۰ قرارداد در روز کاملاً کافی است |
| دامنه | مثلاً `sign.example.com` | رکورد **A** باید به IP سرور اشاره کند |
| پورت‌ها | ۲۲، ۸۰، ۴۴۳ باز | اسکریپت نصب فایروال را خودش تنظیم می‌کند |
| دسترسی | root یا کاربر دارای `sudo` | از طریق SSH |
| فایل‌ها | پوشه/زیپ پروژه‌ی امضاگیر | روی سرور آپلود یا `git clone` کنید |
| لایسنس | کلید `EMZ-XXXXX-…` + کلید عمومی فروشنده | از فروشنده دریافت می‌کنید |

> ⚠️ **ایران:** اگر سرور داخل ایران است و به GitHub/Docker Hub دسترسی ندارید، از میرور Docker (مثلاً `docker.arvancloud.ir`) استفاده کنید یا ایمیج‌ها را از قبل روی سرور بارگذاری کنید.

---

## ۱) اتصال DNS (۵ دقیقه)

در پنل دامنه، یک رکورد بسازید:

```
نوع: A      نام: sign      مقدار: <IP سرور>      TTL: 300
```

با `ping sign.example.com` مطمئن شوید IP درست برمی‌گردد. (تا DNS درست نشود، گواهی HTTPS صادر نمی‌شود.)

---

## ۲) نصب با یک دستور

به سرور وصل شوید (`ssh root@IP`) و پروژه را آنجا بگذارید:

```bash
# اگر پروژه zip است:
apt-get update && apt-get install -y unzip
unzip emzagar.zip -d /opt && cd /opt/emzagar*      # یا: git clone <آدرس-مخزن> /opt/emzagar && cd /opt/emzagar

# نصب (دامنه و ایمیل خودتان را بنویسید):
sudo bash scripts/install-vps.sh sign.example.com you@example.com
```

اسکریپت به‌ترتیب این کارها را می‌کند:

1. Docker را (اگر نباشد) نصب می‌کند؛
2. فایروال را روی ۲۲/۸۰/۴۴۳ تنظیم می‌کند؛
3. فایل `.env` را با رمزهای تصادفی قوی می‌سازد (اگر `.env` از قبل باشد، دست نمی‌زند)؛
4. دیتابیس، برنامه و Caddy (HTTPS خودکار Let's Encrypt) را بالا می‌آورد؛
5. منتظر می‌ماند تا سلامت برنامه تأیید شود؛
6. **بک‌آپ روزانه‌ی ساعت ۳ بامداد** را زمان‌بندی می‌کند.

در پایان آدرس نصب و **کلید نصب** را چاپ می‌کند. زمان بار اول: ۳ تا ۸ دقیقه (ساخت ایمیج).

### نصب دستی (اگر اسکریپت را نمی‌خواهید)

```bash
cp .env.production.example .env && nano .env      # دامنه و رمزها (openssl rand -hex 24)
docker compose -f docker-compose.prod.yml up -d --build
```

---

## ۳) راه‌اندازی اولیه

1. `https://sign.example.com/install` را باز کنید و **کلید نصب** را بدهید.
2. ایمیل و رمز **مدیر کل** را بسازید.
3. از منوی **پلتفرم ← لایسنس و به‌روزرسانی**، کلید لایسنس را وارد کنید و «فعال‌سازی» بزنید.
4. مقدار `LICENSE_PUBLIC_KEY` (که فروشنده می‌دهد) را در `.env` بگذارید تا پاسخ‌های سرور لایسنس **امضا-راستی‌آزمایی** شوند، سپس:
   ```bash
   docker compose -f docker-compose.prod.yml up -d
   ```
5. (اختیاری) SMTP را در `.env` یا از «تنظیمات» پر کنید تا ایمیل بازیابی رمز و اعلان‌ها ارسال شود.

> قطع‌شدن سرور لایسنس سایت شما را **از کار نمی‌اندازد**؛ تا ۱۴ روز «مهلت آفلاین» دارید. با `LICENSE_REQUIRED=1` فقط «صدور قرارداد جدید» بدون لایسنس بسته می‌شود؛ امضای قراردادهای موجود همیشه کار می‌کند.

---

## ۴) اتصال وردپرس (بدون کلید و آدرس)

1. در پنل ابر: **وردپرس و ووکامرس ← دانلود افزونه** (آدرس ابر داخل فایل نوشته شده است).
2. در وردپرس: افزونه‌ها ← افزودن ← بارگذاری ← نصب ← **فعال‌سازی**.
3. خودکار به «ویزارد خوش‌آمدگویی» می‌روید (۵ قدم: کانبان، اتوماسیون، فرم‌ها، ایمنی) و اتصال برقرار می‌شود.
4. در «امضاگیر ← وضعیت سیستم» همه‌ی چراغ‌ها باید **سبز** باشند.

اگر سایت وردپرس پشت فایروال/افزونه‌ی امنیتی است، مسیر `/wp-json/emzagar/` را مجاز کنید (ابر برای تأیید دامنه و دریافت رویداد صدایش می‌زند).

## ۵) به‌روزرسانی

### الف) به‌روزرسانی ابر (روی VPS)

نسخه‌ی جدید را از فروشنده بگیرید و روی سرور اجرا کنید:

```bash
cd /opt/emzagar
./scripts/vps-update.sh /path/to/emzagar-new.zip      # یا:  ./scripts/vps-update.sh --git
```

اسکریپت: بک‌آپ می‌گیرد ← ایمیج فعلی را برای بازگشت نگه می‌دارد ← کد را جایگزین می‌کند (`.env` و دیتا دست‌نخورده) ← می‌سازد ← تست سلامت می‌کند ← **اگر نسخه‌ی جدید بالا نیامد، خودکار به نسخه‌ی قبلی برمی‌گردد.**

> سرویس‌های Docker نمی‌توانند از داخل پنل خودشان را به‌روز کنند (پنل دلیلش را نشان می‌دهد)؛ به‌همین دلیل از این اسکریپت استفاده کنید.

### ب) به‌روزرسانی افزونه‌ی وردپرس (خودکار)

افزونه هر ۱۲ ساعت از **ابر خودتان** نسخه‌ی افزونه‌ی همراهش را می‌پرسد. پس بعد از به‌روزرسانی ابر، همه‌ی سایت‌های وردپرسی شما خودکار نسخه‌ی جدید را می‌گیرند — بدون زدن هیچ دکمه‌ای.

- «امضاگیر ← تنظیمات ← لایسنس و به‌روزرسانی»: وضعیت لایسنس، نسخه‌ی نصب‌شده/جدید و دکمه‌ی «به‌روزرسانی».
- حالت پیش‌فرض: خودکار فقط برای نسخه‌های هم‌خانواده (۲.x ← ۲.y)؛ نسخه‌ی major دستی است. قابل تغییر.
- **پیش از هر به‌روزرسانی، از قوانین/فرم‌ها/تنظیمات پشتیبان گرفته می‌شود** (تب «داده‌ها و پشتیبان» ← «بازگردانی آخرین پشتیبان»).
- بسته فقط از همان دامنه‌ی ابر شما و فقط با HTTPS پذیرفته می‌شود و ساختار آن بررسی می‌شود.

## ۶) پشتیبان‌گیری و بازیابی

بک‌آپ خودکار هر شب در پوشه‌ی `backups/` ذخیره می‌شود (۱۴ روز اخیر نگه داشته می‌شود؛ با `BACKUP_KEEP=30` تغییر دهید):

- `db-زمان.sql.gz` ← دیتابیس
- `storage-زمان.tar.gz` ← امضاها، فایل‌ها و `config.json` (شامل کلید رمزنگاری)

بک‌آپ دستی: `./scripts/vps-backup.sh` — **حتماً هفته‌ای یک‌بار پوشه‌ی `backups` را بیرون از سرور کپی کنید** (مثلاً `rsync` یا `scp`).

### بازیابی

```bash
cd /opt/emzagar
DC="docker compose -f docker-compose.prod.yml"
$DC stop app
# دیتابیس: ساخت دوباره‌ی خالی و بازگردانی
$DC exec -T db psql -U emzagar -d postgres -c "DROP DATABASE emzagar;"
$DC exec -T db psql -U emzagar -d postgres -c "CREATE DATABASE emzagar;"
gunzip -c backups/db-XXXX.sql.gz | $DC exec -T db psql -U emzagar -d emzagar
# فایل‌ها
$DC start app
gunzip -c backups/storage-XXXX.tar.gz | $DC exec -T app tar -C /app -xf -
$DC restart app
```

## ۷) پایش و سلامت

| چه چیزی | کجا |
|---|---|
| سلامت برنامه (Docker/لود‌بالانسر) | `https://sign.example.com/api/health` |
| وضعیت تجمیعی همه‌ی سرویس‌های ابر (UptimeRobot) | `curl -H "Authorization: Bearer $CRON_SECRET" https://sign.example.com/api/health/status` |
| وضعیت هر سایت وردپرسی | «امضاگیر ← وضعیت سیستم» (چراغ سبز/زرد/قرمز) |
| پایش بیرونی هر سایت وردپرسی | آدرس توکن‌دار پایین همان صفحه (`/wp-json/emzagar/v1/health?token=…`؛ ۲۰۰ = سالم، ۵۰۳ = مشکل) |
| از خط فرمان وردپرس | `wp emzagar health` (کد خروج ۱ = مشکل جدی) |

لاگ برنامه: `docker compose -f docker-compose.prod.yml logs -f app`

## ۸) امنیت: چک‌لیست ۵ دقیقه‌ای

- [ ] ورود SSH با کلید (نه رمز)، و `PermitRootLogin prohibit-password`.
- [ ] `.env` فقط برای root خوانا باشد (اسکریپت `600` می‌گذارد) و هرگز در Git قرار نگیرد.
- [ ] `LICENSE_PUBLIC_KEY` پر شده باشد.
- [ ] `SEED_DEMO=0` و `ALLOW_DEV_OTP=0` بماند (پیش‌فرض).
- [ ] بک‌آپ بیرونی هفتگی.
- [ ] در وردپرس: «محدودیت و امنیت» را مرور کنید (سقف روزانه‌ی صدور از فرم، قفل اضطراری).
- [ ] پشت Cloudflare هستید؟ در وردپرس فیلتر `emzagar_client_ip` را برای IP واقعی بازدیدکننده تنظیم کنید.

## ۹) عیب‌یابی سریع

| نشانه | علت محتمل | راه‌حل |
|---|---|---|
| مرورگر «اتصال امن نیست» می‌دهد | DNS هنوز به سرور اشاره نمی‌کند یا پورت ۸۰/۴۴۳ بسته است | DNS و فایروال سرویس‌دهنده (Security Group) را ببینید؛ `docker compose -f docker-compose.prod.yml logs caddy` |
| `/install` بدون کلید باز نمی‌شود | `INSTALL_KEY` فعال است | مقدار آن در `.env` است |
| افزونه «در حال اتصال…» می‌ماند | ابر نمی‌تواند به `/wp-json/emzagar/v1/verify` سایت برسد | فایروال/افزونه‌ی امنیتی؛ «وضعیت سیستم ← دسترسی ابر به وردپرس» |
| چراغ Heartbeat قرمز | WP-Cron اجرا نمی‌شود | برای سایت کم‌بازدید: `*/5 * * * * curl -s https://سایت-شما/wp-cron.php` و `DISABLE_WP_CRON=true` |
| یک بخش افزونه با افزونه‌ی دیگر تداخل دارد | — | «تنظیمات ← ماژول‌ها» همان بخش را خاموش کنید (یا `wp emzagar modules disable forms`) |
| پیشخوان وردپرس باز نمی‌شود | خطای شدید | در `wp-config.php`: `define('EMZAGAR_SAFE_MODE', true);` |
| ایمیل‌ها نمی‌رسد | SMTP تنظیم نیست | `SMTP_*` را در `.env` پر کنید و `up -d` بزنید |
| به‌روزرسانی ابر شکست خورد | — | خودکار برگشت می‌خورد؛ لاگ را ببینید؛ بک‌آپ شب قبل هم هست |
| «ظرفیت دامنه‌ی لایسنس پر است» | لایسنس برای تعداد مشخصی دامنه است | از فروشنده یک دامنه را آزاد کنید یا لایسنس را ارتقا دهید |

## ۱۰) حذف

```bash
cd /opt/emzagar
docker compose -f docker-compose.prod.yml down -v      # ⚠️ دیتابیس و فایل‌ها را هم پاک می‌کند! قبلش بک‌آپ بگیرید
crontab -l | grep -v vps-backup.sh | crontab -
```

حذف افزونه از وردپرس، اتصال را در ابر می‌بندد (کلید API باطل می‌شود)؛ قراردادها و قالب‌ها در حساب شما می‌ماند. **پیش از حذف، «خروجی کامل داده‌ها» را بگیرید.**
