# کیف اسناد امضاکننده و حلقه‌ی ویروسی (فاز ۳)

## مسئله
امضاکننده‌ی مهمان بعد از امضا دیگر دلیلی برای برگشتن ندارد؛ پس هر امضا یک «بن‌بست رشد» بود.

## راه‌حل: «کیف اسناد» (`/vault`)
هویت کیف = **شماره‌ی موبایل تأییدشده با OTP** (نه یک ردیف `users`). مهمان‌ها به‌ازای هر فضای کاری یک ردیف جدا دارند؛
کیف همه‌ی ردیف‌های همان شماره را در همه‌ی فضاهای کاری یک‌جا نشان می‌دهد، بدون شکستن ایزولاسیون فضاها.

### قاعده‌ی تعلق سند (ضد نشت)
ردیف امضاکننده‌ای با `users.mobile = M` که: مهمان است، یا خودش با OTP امضا کرده (`otp_verified_at`)،
یا همین کیف او را به حساب واقعی ارتقا داده (`vault_profiles.upgraded_user_id`).
کسی که فقط شماره‌ی دیگری را در پروفایل خودش نوشته، اسناد آن شماره را نمی‌بیند.

### ورود
1. **یک‌لمسی** از صفحه‌ی «امضای شما ثبت شد» (`/sign/[token]`): نشست OTP امضا هنوز معتبر است؛ بدون کد دوباره.
   اگر نشست تمام شده باشد، همان‌جا کد پیامکی به همان موبایل می‌رود (بدون تایپ شماره).
2. **مستقیم** از `/vault`: موبایل + OTP. پیامک فقط برای شماره‌ای که سند دارد ارسال می‌شود؛ پاسخ در هر دو حالت یکسان است.
3. پیامک «نسخه‌ی نهایی» مهمان حالا لینک کیف را هم دارد؛ صفحه‌ی پیگیری ارسال سریع هم به کیف لینک می‌دهد.

نشست: کوکی HttpOnly + HMAC، ۳ روز. همه‌ی عملیات (PDF، ZIP، ادامه‌ی امضا) فقط با همین نشست و فقط برای اسناد خودِ موبایل.

### مدیریت اسناد
- صندوق یکپارچه: «منتظر امضای من» / «منتظر دیگران» / «نهایی‌شده» / «بسته‌شده» / «بایگانی»
- «مشاهده و امضا» برای اسناد منتظر (به لینک اختصاصی می‌رود؛ OTP امضا همچنان لازم است)
- دانلود PDF رسمی هر سند و ZIP همه‌ی اسناد (با `index.txt` شامل SHA-256)
- جستجو، سنجاق، بایگانی، یادداشت خصوصی، هشدار پایان مدت قرارداد (۶۰ روز)

## موتور رشد
```
امضا ─▶ کیف (ارزش فوری) ─▶ ساخت حساب ۳۰ثانیه‌ای ─▶ اولین قرارداد ─▶ پاداش دوطرفه ─▶ امضاکننده‌های جدید
```
- **انتساب اولین‌لمس:** فرستنده‌ی اولین قراردادِ کسب‌وکاری که این شماره با OTP امضا کرده، «دعوت‌کننده» رسمی می‌شود.
  کد دعوتی برای وارد کردن وجود ندارد؛ از موتور موجود `referrals` استفاده می‌شود (پاداش دعوت‌کننده + هدیه‌ی دعوت‌شده،
  فقط پس از ایمیل تأییدشده و اولین قرارداد واقعی؛ سقف و ضدتقلب موجود برقرار است). ارسال سریع منتسب نمی‌شود (مالک سیستمی).
- **ارتقای بدون اصطکاک:** فقط ایمیل + رمز. همان ردیف مهمان با `upgradeGuestToUser` به کاربر واقعی تبدیل می‌شود
  و تاریخچه‌ی امضاها بی‌مهاجرت می‌ماند؛ سپس فضای کاری ساخته می‌شود و تأیید ایمیل مثل ثبت‌نام عادی است.
- **بدون ثبت‌نام:** لینک «ارسال سریع» (`/quick`).
- **اندازه‌گیری:** جدول `vault_profiles` + کارت «قیف حلقه‌ی ویروسی» در `/platform`
  (امضاکننده‌ی تأییدشده ← وارد کیف ← بازگشته ← حساب ساخته ← قرارداد فرستاده).

## تنظیمات
- `VAULT_ENABLED=0` یا تنظیم سراسری `vault_enabled = 0`: غیرفعال‌سازی کامل.
- مقدار پاداش‌ها از همان تنظیمات «دعوت دوستان» (`referral_cfg`) خوانده می‌شود.

## جدول‌های جدید
`vault_profiles` (پروفایل سبک و قیف رشد هر موبایل) و `vault_prefs` (سنجاق/بایگانی/یادداشت). ساختار فقط در `schema.ts` است
و نصب‌کننده آن را به‌صورت خودکار می‌سازد.
