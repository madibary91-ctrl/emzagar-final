# امضاگیر (Emzagar) — پلتفرم SaaS امضای آنلاین قرارداد

Next.js 16 (App Router) · PostgreSQL · Drizzle ORM · Tailwind 4

## نصب (بدون خط فرمان)
خریدار فقط بسته را روی هاست آپلود می‌کند و آدرس سایت را باز می‌کند؛ **نصب‌کننده‌ی وب** (`/install`) دیتابیس را می‌آزماید (و در صورت نبود می‌سازد)، کلید امنیتی تصادفی می‌سازد، جدول‌ها را می‌سازد، حساب مدیر را می‌سازد و وارد می‌کند — بدون `.env`، بدون `drizzle-kit`، بدون ری‌استارت.

| روش | برای چه کسی | راهنما |
|---|---|---|
| بسته‌ی آماده + cPanel «Setup Node.js App» | مبتدی | `docs/INSTALL-FA.md` |
| `docker compose up -d` | VPS / Coolify / Portainer | `docker-compose.yml` |
| **`sudo bash scripts/install-vps.sh دامنه ایمیل`** (HTTPS خودکار + بک‌آپ روزانه) | خریدار VPS — Turnkey | `docs/DEPLOYMENT-GUIDE-FA.md` |
| `npm ci && npm run build && npm start` | توسعه‌دهنده | همان راهنما |

ساخت بسته‌ی فروش: `node scripts/build-release.mjs` ← `release/emzagar-<نسخه>.zip`.
`src/db/schema.ts` تنها منبع حقیقت ساختار دیتابیس است؛ SQL نصب‌کننده در لحظه از آن ساخته می‌شود (`src/db/ddl.ts`) و مرحله‌ی دستی ندارد. برای CI: `node scripts/gen-schema-sql.mjs` همگامی با drizzle-kit را راستی‌آزمایی می‌کند.
اگر دیتابیس را پاک کردید و می‌خواهید نصب‌کننده دوباره اجرا شود، فایل `storage/installed.lock` را حذف کنید.

## ربات‌های پیام‌رسان: بله و تلگرام (جدید)
لینک امضا، وضعیت قرارداد، یادآوری و اعلان‌ها **داخل بله و تلگرام** (به‌جای پیامک/ایمیل): ربات دوطرفه با دستورهای `/pending` `/contracts` `/status` `/summary`، دکمه‌ی «یادآوری» برای تیم، **کد تأیید امضا از پیام‌رسان** (فقط به چت با شماره‌ی گواهی‌شده؛ پیامک فقط در صورت ناموفق‌بودن)، نسخه‌ی نهایی (لینک امن یا PDF)، اتصال حساب با کد یک‌بارمصرف، «اشتراک شماره» برای امضاکننده‌ی مهمان، حالت وب‌هوک و Polling (بدون HTTPS)، رله‌ی API برای تلگرام در ایران، ربات پلتفرم و ربات اختصاصی هر فضای کاری. ایتا نیز به «اعلان پیام‌رسان» (یک‌طرفه به کانال/گروه) اضافه شد. پنل: `/admin/messengers` و `/platform/messengers` — «حساب من ← پیام‌رسان‌ها». راهنما: `docs/MESSENGERS-FA.md`.

## مهر شرکتی، شاهد، پاراف و امضای هم‌زمان (فاز ۶ — B2B)
قراردادهای شرکتی ایران: **مهر شرکتی** (آپلود/ساخت مهر، الزام سمت سرور، درج روی PDF)، **شاهد** (فقط گواهی می‌دهد و شرط نهایی‌شدن است)، **پاراف همه‌ی صفحات** (پایین تک‌تک صفحات + هش در اثر انگشت سند) و **امضای هم‌زمان/مرحله‌ای** کنار امضای ترتیبی — همه بر پایه‌ی یک مفهوم واحد «مرحله‌ی امضا». همه‌چیز اختیاری است و اسناد ساده مثل قبل کار می‌کنند. راهنما: `docs/PHASE6-FA.md`.

## یکپارچگی عمیق با وردپرس (جدید)
افزونه‌ی ۲٫۱ فقط «امضا» نیست؛ **مرکز فرماندهی کسب‌وکار** داخل وردپرس است: نشان زنده‌ی قراردادهای منتظر امضا روی نوار مدیریت، ویجت پیشخوان، صف اقدام با یادآوری یک‌کلیکی، گزارش هفتگی ایمیلی و نمایش ارزش‌آفرینی؛ **دروازه‌ی قرارداد** (قفل صفحه/محصول/بخشی از متن تا امضا، خرید فقط پس از امضا، نقش خودکار، شاخص آفلاین امضاها، API توسعه‌دهنده)؛ **نشان اعتماد** عمومی (`/trust/<slug>`)؛ و **عمق یکپارچگی** (امتیاز و گام بعدی در وردپرس و `/admin/wordpress`). راهنما: `docs/DEEP-INTEGRATION-FA.md`.

## مرکز فرماندهی کامل در وردپرس (افزونه‌ی ۲٫۲ — جدید)
مدیر سایت دیگر برای کارهای قرارداد از وردپرس بیرون نمی‌رود: **میز کار قراردادها** (کانبان، جزئیات، یادآوری، لغو، PDF، صدور)، **پالت فرمان Ctrl+K** برای جستجو و اقدام سریع در کل پیشخوان، **اعلان زنده‌ی امضا** (Heartbeat)، **اتوماسیون «اگر … آنگاه»** با دستورهای آماده، **فرم‌ها ← قرارداد** (CF7، WPForms، Gravity، Elementor Pro، Fluent)، ارسال قرارداد از فهرست کاربران و **WP-CLI**. API جدید: `/api/v1/hub/{pipeline,contract/<id>,search}` · `/api/v1/contracts/<id>/{cancel,pdf}`. راهنما: `docs/DEEP-INTEGRATION-FA.md`.

## اتصال بدون تنظیم افزونه‌ی وردپرس (جدید)
کاربر فقط **دانلود ← نصب ← فعال‌سازی** می‌کند: افزونه خودکار با ابر دست‌داد می‌دهد، مالکیت دامنه با یک چالش REST تایید می‌شود، فضای کاری + قالب‌های نمونه + کلید API ساخته می‌شود (کلید فقط روی سرور وردپرس ذخیره می‌شود) و از منوی وردپرس با SSO یک‌کلیکی وارد پنل می‌شود. اتصال خودترمیم است. جزئیات: `docs/WORDPRESS.md` — صفحه‌ی پنل: `/admin/wordpress` — دانلود ZIP پیکربندی‌شده: `/api/wordpress/plugin`.

## امکانات این نسخه
1. **کلید هوش مصنوعی در تنظیمات** — `/admin/settings`: فیلد ماسک‌شده (با نمایش/پنهان)، انتخاب مدل (فهرست پیشنهادی + دریافت فهرست زنده)، تست اتصال، نمایش سهمیه. کلید با AES‑256‑GCM رمزنگاری و در دیتابیس ذخیره می‌شود (هرگز به مرورگر برنمی‌گردد). `.env` فقط پیش‌فرض اختیاری پلتفرم است.
2. **تیکت پشتیبانی** — کاربران: `/support` (ثبت، پیگیری، پاسخ، بستن + امتیاز). مدیر کل: `/platform/tickets` (فیلتر وضعیت/اولویت/دسته، جستجو، پاسخ، یادداشت داخلی، تغییر وضعیت: باز ← در حال بررسی ← بسته، اعلان ایمیلی) و `/platform` (آمار کل پلتفرم).
3. **افزونه‌ی وردپرس/ووکامرس/المنتور** — `wordpress-plugin/emzagar-contracts` (راهنما: `docs/WORDPRESS.md`). نقاط API جدید: `GET /api/v1/contracts` · `/templates` · `/stats`. **همگام‌سازی دوطرفه‌ی ووکامرس (سفارش‌ها، مشتریان، وضعیت امضا لحظه‌ای):** `docs/WOOCOMMERCE-SYNC.md` — پنل: `/admin/woocommerce`.
4. **ارتقاهای دیگر** — رمزنگاری رمزهای SMTP/پیامک در دیتابیس، نشان تعداد پاسخ‌های جدید روی منو، صفحه‌ی مدیریت پلتفرم، مستندات API به‌روز.

## نسخه‌ی ۲۰۲۶ — قابلیت‌های جدید
1. **تحلیل ریسک قرارداد** — `/admin/risk`: موتور قواعد فارسی (بندهای ضروری ناقص، اختیار یک‌طرفه، تمدید خودکار، جریمه‌ی سنگین، جاهای خالی، ابهام) که همیشه رایگان کار می‌کند + تحلیل عمیق با هوش مصنوعی (JSON ساختاریافته، ضد Prompt‑Injection، از سهمیه‌ی AI کم می‌شود). گزارش‌ها ذخیره می‌شوند؛ دکمه‌ی «تحلیل ریسک» روی صفحه‌ی هر قرارداد.
2. **اشتراک و پرداخت (درآمد پلتفرم)** — `/admin/billing` و صفحه‌ی عمومی `/pricing`: طرح‌ها **کاملاً پویا و در دیتابیس** هستند و مدیر کل از «مدیریت پلتفرم ← طرح‌های اشتراک» (`/platform/plans`) آن‌ها را می‌سازد/ویرایش/حذف می‌کند (قیمت، مدت‌ها و تخفیف هر مدت، سقف قرارداد/عضو/AI، عمومی یا خصوصی، پیش‌فرض، طرح پاداش دعوت؛ راهنما: `docs/PLANS-FA.md`)، تخفیف پرداخت چندماهه، درگاه زرین‌پال (مبلغ فقط سمت سرور محاسبه می‌شود، تایید تراکنش idempotent)، پاسخ `402` در API هنگام رسیدن به سقف. درآمد در `/platform` دیده می‌شود.
3. **هوش تجاری** — `/admin/insights`: قیف تبدیل (صدور ← بازشدن ← امضا)، روند ۳۰ روزه، ساعت‌های اوج امضا، انباشت قراردادهای معطل، ارزش سفارش‌های منتظر امضا و توصیه‌های خودکار.
4. **استعلام عمومی اصالت سند + QR** — `/verify/<sha256>`: بازمحاسبه‌ی اثر انگشت و تشخیص دستکاری؛ QR روی نسخه‌ی چاپی/PDF؛ نام امضاکنندگان ماسک می‌شود و متن قرارداد هرگز نمایش داده نمی‌شود.
5. **PWA** — manifest، آیکون‌های maskable، Service Worker امن (هیچ صفحه‌ی احرازهویت‌شده/API کش نمی‌شود)، صفحه‌ی آفلاین و دعوت به نصب.
6. **Command Palette** — `Ctrl/⌘ + K` در پنل: پرش به صفحه‌ها و جستجوی قرارداد، مشتری و قالب.

## امنیت حساب و صدور مجدد (جدید)
1. **حساب من** — `/account`: ویرایش نام و موبایل (موبایل مبنای OTP امضاست؛ تغییر آن رمز فعلی می‌خواهد و شماره‌ی قراردادهای در انتظار هم به‌روز می‌شود)، تغییر رمز عبور (سایر نشست‌ها باطل می‌شوند و ایمیل هشدار می‌رود). دسترسی از کارت کاربر در منوی کناری، چیپ نام در هدر و Ctrl+K.
2. **ورود دومرحله‌ای (TOTP، RFC 6238)** — از همان صفحه فعال می‌شود: QR + کلید دستی، تأیید با کد اول، ۸ کد بازیابی یک‌بارمصرف (فقط هش ذخیره می‌شود)، ساخت دوباره‌ی کدها و غیرفعال‌سازی با رمز + کد. راز با AES‑256‑GCM رمزنگاری می‌شود، کد مصرف‌شده دوباره پذیرفته نمی‌شود (ضد Replay)، تلاش‌ها محدود است و پس از رمز درست فقط یک کوکی ۵ دقیقه‌ای میانی ساخته می‌شود (نشست کامل تا تأیید کد ساخته نمی‌شود). بدون وابستگی جدید؛ جدول `user_totp` به نصب‌کننده‌ی وب هم اضافه شده است.
3. **کپی و صدور مجدد قرارداد** — دکمه‌ی «کپی قرارداد» (و «صدور مجدد» برای قراردادهای رد/منقضی/لغوشده) روی صفحه‌ی قرارداد: یک پیش‌نویس جدید با همان مشتری، ترتیب امضاکنندگان و متن ساخته می‌شود؛ شماره و تاریخ قدیمی به متغیر برمی‌گردند و هنگام انتشار تازه می‌شوند. پیش‌نویس سقف ماهانه‌ی طرح را مصرف نمی‌کند.

## اصلاحات فاز بازبینی ۲۰۲۶
- جعل‌پذیری `X-Forwarded-For` (دور زدن محدودیت نرخ) → خواندن IP از سمت راست با `TRUSTED_PROXY_HOPS`.
- API صدور قرارداد هنگام خطا ۵۰۰ خام می‌داد؛ اکنون خطای کنترل‌شده (۴۰۲/۵۰۰).
- یکسان‌سازی زمان پاسخ ورود برای ایمیل ناشناس (جلوگیری از شمارش حساب‌ها).
- هدرهای HSTS، COOP، `frame-ancestors`، و کش‌نشدن `sw.js`.
- سقف اعضای تیم هنگام دعوت، و سقف قرارداد هنگام انتشار پیش‌نویس/صدور گروهی.

## اصلاحات فاز بازبینی (امنیت و باگ)
- **هدرهای امنیتی فعال شدند**: تنظیمات در `src/next.config.ts` بود و Next.js آن را نمی‌خواند؛ به ریشه منتقل شد (X-Frame-Options، nosniff، …).
- جلوگیری از **SSRF** در آدرس سرویس AI و میزبان SMTP (`src/lib/ssrf.ts`)، `redirect: "error"` روی فراخوانی‌های بیرونی.
- **تزریق HTML در ایمیل‌ها** (نام کاربر، عنوان قرارداد، نام فضای کاری) و بدنه‌ی قرارداد در ایمیل نهایی: escape/sanitize شد.
- **Host Header Injection** در لینک بازیابی رمز: با `APP_URL` قابل قفل شدن است.
- **Race condition** در شمارنده‌ی تلاش OTP و قفل لینک رمزدار → افزایش اتمیک (جلوگیری از دور زدن سقف تلاش با درخواست‌های موازی).
- لینک PDF در ایمیل نهایی هنگام خالی بودن «آدرس سایت» نسبی/خراب می‌شد؛ رفع شد. اعتبارسنجی `app_url`.
- کوکی باز شدن قفل لینک: پرچم `secure` اضافه شد.
- کلیدهای محرمانه‌ی قدیمی (متن ساده) هنگام خواندن سازگارند و با اولین ذخیره رمزنگاری می‌شوند.

## امنیت و پایداری — سه اصلاح بحرانی (CR-03 · CR-04 · CR-05)

### CR-03 — نصب‌کننده‌ی وب (اولین بازدیدکننده دیگر مدیر کل نمی‌شود)
- نصب‌کننده «همیشه» کلید نصب می‌خواهد: `INSTALL_KEY` (محیط) یا کلید تصادفی ۱۴۴ بیتی در `storage/install-key.txt` (مجوز 0600 + چاپ در لاگ سرور). پس از نصب، فایل کلید حذف می‌شود. تلاش‌های ناموفق سراسری شمرده می‌شود (۲۰ تلاش ← قفل ۱۵ دقیقه‌ای).
- وضعیت نصب سه‌حالته است: `installed` / `fresh` / `unknown`. اگر دیتابیس پیکربندی شده ولی خوانده نمی‌شود (قطعی، خطای دسترسی) و lock-file هم نیست، حالت «نامعلوم» است و **همه‌ی مراحل بسته می‌مانند**؛ پس آدرس دیتابیس بازنویسی نمی‌شود و مدیر جدید ساخته نمی‌شود.
- `INSTALL_OPEN=1` فقط انصراف صریح برای CI/آزمون محلی است (اسکریپت‌های e2e/qa آن را می‌گذارند) و در حالت «نامعلوم» هم بسته می‌ماند.
- آزمون: `tests/integration/install-hardening.test.ts` · `install-fail-closed.test.ts`.

### CR-04 — بک‌آپ کامل و جدا از داده‌ی اصلی
- بک‌آپ اکنون شامل **مدارک KYC** (همان فایل‌های رمزنگاری‌شده) و **SESSION_SECRET** است. راز هرگز متن ساده نیست: با «sealed box» (X25519 + HKDF-SHA256 + AES-256-GCM) فقط برای **کلید بازیابی** مالک مهر می‌شود (`secrets.sealed.json`). کلید خصوصی (`emz-rk1-…`) روی سرور ذخیره نمی‌شود و فقط یک بار نمایش داده می‌شود.
- ساخت کلید: `/platform` ← «ساخت کلید بازیابی» یا `npm run backup -- keygen`. تا ساخته نشود، بک‌آپ بدون راز گرفته و هشدار `secret-not-sealed` نشان داده می‌شود.
- **نسخه‌ها جدا از داده‌ی اصلی:** Docker: volume جدای `backups` (`BACKUP_DIR=/app/backups`)؛ همه‌ی استقرارها: `BACKUP_MIRROR_DIRS=/mnt/a,/mnt/b` برای کپی هم‌زمان (با راستی‌آزمایی در مقصد و سیاست نگهداری جدا). اگر هیچ نسخه‌ای بیرون از volume داده نباشد، هشدار `backups-inside-data-volume` در `/platform` نشان داده می‌شود.
- تمرین بازیابی: `npm run backup -- verify --key emz-rk1-…` · بازیابی: `npm run restore -- <پوشه> --key emz-rk1-… --yes` (راز در `storage/config.json` نوشته می‌شود؛ کلید غلط/نبود کلید ← پیش از هر تغییر متوقف می‌شود). `scripts/vps-backup.sh` هم اکنون storage را رمزنگاری می‌کند (`BACKUP_PASSPHRASE`) و به `BACKUP_MIRROR` کپی می‌کند.
- آزمون: `tests/integration/backup-complete.test.ts`.

### CR-05 — امضای دیجیتال به‌روزرسانی افزونه‌ی وردپرس
- مدل اعتماد: ابر فقط **پخش‌کننده** است. هر انتشار با کلید خصوصی **Ed25519 ناشر** (آفلاین، نه روی ابر) امضا می‌شود: `RELEASE.json` (SHA-256 همه‌ی فایل‌ها + نسخه) و `RELEASE.sig`. کلیدهای عمومی (اصلی + جایگزین اضطراری) در `class-emzagar-release.php` **پین** شده‌اند.
- افزونه‌ی نصب‌شده، هم zip (پیش از استخراج) و هم پوشه‌ی استخراج‌شده (فیلتر `upgrader_source_selection`، عبور اجباری از هر مسیر دانلود) را می‌سنجد: امضا، فهرست دقیق فایل‌ها، SHA-256 تک‌تک فایل‌ها، لینک نمادین/مسیر مشکوک/حجم غیرعادی، و ضد بازگشت به نسخه‌ی قدیمی‌تر. `emzagar-config.php` فقط با قالب ثابت و آدرس ابر خود افزونه پذیرفته می‌شود؛ هیچ PHP دلخواهی از ابر عبور نمی‌کند.
- ابر هم فقط بسته‌ی امضاشده‌ی معتبر را عرضه می‌کند (`/api/v1/connect/update-check`).
- گردش کار ناشر: `npm run plugin:keygen -- <keyId> <فایل>` (یک بار؛ خروجی را در `KEYS` بگذارید) ← پس از هر تغییر در `wordpress-plugin/`: `EMZ_RELEASE_SIGNING_KEY_FILE=… EMZ_RELEASE_KEY_ID=… npm run plugin:sign` ← `npm run plugin:verify` (در `build-release.mjs` خودکار اجرا می‌شود).
- آزمون: `tests/unit/wp-release.test.ts` (کد واقعی PHP را اجرا می‌کند؛ `PHP_BIN` و در صورت نبود sodium، `SODIUM_COMPAT_DIR`).
